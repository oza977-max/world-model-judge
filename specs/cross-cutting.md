### Expert Discovery: Numerical Computing

The existing GVM roster has no specialist for numerical integration or floating-point reproducibility — both load-bearing here. Per the discovery protocol:

**Ernst Hairer, Syvert Nørsett & Gerhard Wanner** — *Solving Ordinary Differential Equations I: Nonstiff Problems* (2nd ed.), Springer (1993)
- **Method choice follows problem structure**: fixed-step explicit Runge–Kutta methods are the reference choice for smooth non-stiff systems like ours; their local truncation error is well-characterised, which is what WD-3's drift measurement quantifies.
- **Conserved quantities drift under generic integrators**: a non-symplectic method does not preserve energy or other invariants exactly — the drift is systematic, measurable, and must be bounded rather than assumed away (exactly WD-3's second clause).

**David Goldberg** — "What Every Computer Scientist Should Know About Floating-Point Arithmetic", *ACM Computing Surveys* 23(1) (1991)
- **Floating-point arithmetic is deterministic but not associative**: the same operations in the same order give the same bits; a different summation order gives different bits. Reproducibility (NF-1) is therefore an *ordering* discipline, not a hardware property.
- **Same platform, same libraries, same order → same bits**: NF-1's "machines of the same platform" scope is exactly the scope within which IEEE-754 double arithmetic is bit-reproducible.

## ADR-001 — Tech stack: pure NumPy scientific Python

**Decision:** Python 3.12, with NumPy as the only numerical dependency, Matplotlib as the only charting dependency, pytest as the only test dependency. The two learned models (MU-5) are hand-rolled NumPy MLPs — no deep-learning framework.

**Status:** Accepted (user decision, 25 Aug 2026).

**Context:** NF-1 requires byte-identical verdicts across runs and machines of the same platform. NF-2 requires laptop-scale runtime. NF-3 requires a small, named, long-established dependency set. The state spaces are 2–4 dimensions; the models are deliberately trivial (MU-10). [Requirement: NF-1, NF-2, NF-3, MU-5, MU-10]

**Options considered:**
1. **Pure NumPy** — hand-rolled MLPs (~150 lines including backprop). Strongest determinism (single-threaded, seeded, no framework kernels), smallest dependency set, code readable end-to-end by Dev.
2. **NumPy + PyTorch (CPU)** — standard tooling, less hand-rolled code; but a ~2 GB dependency for two tiny MLPs, framework-level nondeterminism to fight (threaded kernels, versioned numerics), and a weaker NF-3 story.
3. **Stdlib only** — maximum purity; but slow, unreadable matrix code, and Matplotlib is required for charts anyway, so the purity is spoiled regardless.

**Decision rationale:** Option 1. At this problem size a framework buys nothing and costs determinism. Writing backprop by hand is a feature for this project: the judge's subject matter is *trust in learned models*, and a reader can verify every line of what was learned.

**Consequences:** We own the correctness of the MLP implementation (mitigated: gradient-check test against finite differences, part of the models spec). Exact package versions must be pinned (see Dependency Budget). No GPU path exists, which NF-2 makes irrelevant.

## ADR-002 — Determinism strategy

**Decision:** Determinism is achieved by four enforced rules: (1) single-threaded execution, (2) one seeded generator per component with explicit seed plumbing, (3) no wall-clock, filesystem, or environment reads inside any computation path, (4) canonical serialization for every artefact that NF-1 compares.

**Status:** Accepted.

**Context:** NF-1 (byte-identical verdicts), WD-7 (byte-identical trajectories), MU-8 (reproducible training), JU-12 (pure judge). Assumption 5 of the requirements flags this as the assumption most likely to bite. [Requirement: NF-1, WD-7, MU-8, JU-12] [Test: TC-NF1-01, TC-NF1-02, TC-NF1-03, TC-NF1-04, TC-WD7-01, TC-WD7-02, TC-MU8-01, TC-JU12-01, TC-JU12-02]

**The four rules, precisely:**

1. **Single-threaded.** The entry point sets `OMP_NUM_THREADS=1`, `OPENBLAS_NUM_THREADS=1`, `MKL_NUM_THREADS=1` **before importing NumPy**. Unordered parallel reduction is the canonical source of run-to-run float drift (Goldberg: non-associativity); we remove it entirely. NF-2's minutes-scale budget survives this — the workloads are small. **What the test suite can actually assert (design-review-005 repair — Round 5 found "the test suite asserts NumPy reports single-threaded configuration" names no real NumPy API: NumPy exposes no runtime thread-count introspection, and the standard tool `threadpoolctl` is not in the dependency budget):** the startup gate asserts the three environment variables are set to `"1"` in `os.environ` at process start, *before* NumPy is imported (this is the control that actually determines BLAS threading), and the ten-run byte-identity gate (TC-NF1-01) is the empirical backstop that would catch any residual threaded-reduction nondeterminism. The residual is disclosed: commanding single-thread via the env vars is verifiable; that OpenBLAS/MKL *honoured* it is not runtime-introspectable without a dependency this project deliberately excludes — so the env-var assertion plus byte-identity is the honest, in-budget form of the guarantee, not a false claim of thread-count introspection.
2. **Seeding — content-addressed derivation, pinned (design-review-005 repair — Round 5 executed a demonstration that the v1.4 wording named two non-interchangeable APIs, "jumped/spawned", with no derivation rule, and that the implementation most consistent with the project's own sorted-name conventions, positional `spawn`, reassigns *every* model's stream when one alphabetically-earlier model is added — silently changing weights and verdicts, defeating MU-9 at the trained-artefact level).** All randomness flows from `numpy.random.Generator(numpy.random.PCG64(seed))` instances created at the orchestration layer and passed down explicitly. No module creates its own generator from entropy; no code calls the legacy global `numpy.random.*` functions. **Every component's seed is derived by content, not by position, through `SeedSource` — pinned exactly, not by example (design-review-006 repair — Round 6 executed four textually-conforming readings of the v1.5 "e.g." hash and got four different `Generator` streams, so two spec-conforming builds were byte-different; the construction below is now mandated, and two independent implementations of it were run and produced identical keys — `C3 two-impl convergence: True`).** The pinned pure function, defined in **`wmj/models/base.py`** (moved from `wmj/harness/seeds.py` — design-review-006: fixtures must derive `"direct"`'s stream, models cannot import the harness, and the function is pure with no I/O so it belongs in the shared model-facing base module):

```
component_key(*parts) -> tuple[int]:        # PINNED, no wildcard
    for p in parts:                          # design-review-008 I5: every part must
        if not isinstance(p, str):           # already be str — component_key(1, "a")
            raise SeedKeyError(              # and component_key("1", "a") joined to the
                f"seed key part {p!r} is not a str "  # same text under the old str(p)
                f"(type {type(p).__name__}); the caller "  # coercion, an int/str collision
                f"must pass its own str() form explicitly")  # the ':' fix didn't address —
        if ":" in p:                         # rejecting non-str at construction closes it,
            raise SeedKeyError(              # same as the colon guard below
                f"seed key part {p!r} contains ':' (reserved delimiter); "
                f"model/world/region/purpose names must not contain ':'")
    joined = ":".join(parts).encode("utf-8")
    digest = hashlib.blake2b(joined, digest_size=8).digest()
    return (int.from_bytes(digest, "big"),)  # ONE big-endian 64-bit int, as a 1-tuple

SeedSource (frozen, wmj/models/base.py; constructed by the harness, handed to every factory as data):
    run_seed: int
    my_name: str | None                     # the factory's own model name, or None for harness-side use
    rng(*purpose)      -> Generator          # = rng_for(my_name, *purpose)
    rng_for(*parts)    -> Generator          # Generator(PCG64(SeedSequence(entropy=[run_seed, *component_key(*parts)])))
```

Because the key is a function of *identity*, not iteration order, **adding a model/world/region provably never shifts any other component's stream** — executed and confirmed (`C3 no-shift (add 'aardvark'): True`). This "provably" holds only because the join is injective, which requires (a) that **no part contain the `:` delimiter** — design-review-007 executed the collision (`component_key('a:b','c') == component_key('a','b:c')`, identical streams) and the fix rejects any such part at construction (above, `SeedKeyError`) — and (b) that **every part already be a `str`** — design-review-008 executed the sibling collision the colon fix left open (`component_key(1, "a") == component_key("1", "a")`: the old `str(p)` coercion inside the function collapsed an int and its own decimal string to the same joined text), and the fix now rejects any non-`str` part at construction too, pushing the `str()` conversion (if any) to the caller, where the "decimal, no padding" convention below is the caller's job to honour consistently, not something `component_key` can enforce for them. Both are enforced by construction now, not by luck of the current vocabulary (TC-NF1-07, TC-NF1-08, new). Two further consequences the v1.5 wording missed, both pinned and executed:
- **A `purpose` string is a first-class key part (design-review-006 C4 — Round 6 found the v1.5 key {model, world, region, index} had no discriminator, so MU-7 training-starts, JU-8's 200 eval-starts, and WD-4's 64 benchmark-starts all keyed to the same seed for the `"training"` region and would collide, defeating train/eval disjointness and trial independence).** The harness draws each as `seeds.rng_for(world, region, "train-starts" | "eval-starts" | "benchmark-starts")` — distinct purposes, executed distinct (`C4 purpose keys differ: True`).
- **`blake2b` is mandatory over Python's `hash()`** (salted per process — verified: two subprocesses give different `hash()` but identical `blake2b`), and `index`/member id, when present, is just another `part` (decimal, no padding).

`SeedSource` replaces the bare `rng` argument in the factory signature (models spec ADR-M1). TC-NF1-03 asserts the no-shift property; TC-NF1-04 (new) asserts two-implementation convergence of `component_key` from the pinned text alone.
3. **No ambient inputs.** Nothing in worlds, models, or judge reads the clock, the filesystem, environment variables, or network. The judge specifically is a pure function (JU-12): its entire call graph takes arguments and returns values. File I/O happens only in the orchestration and reporting layers, at the edges. This includes run-identifying metadata — platform string, prereg commit SHA — which the harness reads and attaches to the `JudgedResult` envelope (Data-Model Overview) *after* calling the judge, never inside it (design-review fix: an earlier draft of the judge spec's Verdict schema carried a `meta` block the judge could not have produced without violating this rule). **Enforcement, scoped honestly (design-review-004/005 repair).** The judge's purity is enforced by two controls with clearly-divided roles, plus an explicit threat model (design-review-005 — Round 5 executed three reflection escapes of the static gate, `().__class__.__base__.__subclasses__()`, `np.get_include.__globals__['os']`, `getattr(np,"__builtins__")["eval"]`, and showed the static AST gate cannot be a security boundary because no finite identifier list bounds Python's reflection graph):
- **The runtime purity harness (TC-JU12-01) is a best-effort tripwire over the *known* ambient-capability surface — NOT a completeness guarantee; NF-1 byte-identity is the actual backstop (design-review-007 repair, execution-verified — see below for what changed and why the completeness claim is dropped).** It executes the judge's full call graph in an environment where, for every ambient capability *it can name*, the harness **mutates the real shared object every holder already references, in place, at every level that object is independently bound** — never a bare `sys.modules` swap (Round 6 proved the swap never reaches numpy's pre-bound `os`; Round 7 confirmed mutate-in-place fires on the same `np.get_include.__globals__['os'].getcwd()` reflection route) — **with exactly one disclosed exception (`numpy.datetime64`, below), which is a rebind because Python gives no other option for that type.** Design-review-008 found "mutate in place" had itself been applied at only the *first* binding found for two capabilities (`os.environ`'s instance rather than its class; `numpy.random`'s top-level names rather than its private submodules too) — both now patch every reachable binding, not just one. Concretely, run before writing in Round 8's fix pass (extending Round 7's):
  - **`os`:** `setattr(os, name, raise)` for the effectful functions (`system`, `getcwd`, `getenv`, `urandom`, `getpid`, `listdir`, `stat`, `fork`, `execve`/`exec*`, `posix_spawn`, `spawnv` — design-review-008 I10 added the process-creation primitives, which Round 7's illustrative list omitted while `subprocess` guarding does not cover them). **`os.environ` is guarded by mutating `os.environ`'s real *class* (`os._Environ`) in place — not the instance** (design-review-008 C1 repair, executed: Round 7's instance-level `os.environ.get = raise` guarded `.get()` but Python resolves `obj[x]`, `x in obj`, `dict(obj)` against the *type*, never the instance `__dict__`, for any new-style class — a language rule, not an evasion, so `os.environ["HOME"]`/`"HOME" in os.environ`/`dict(os.environ)` all leaked clean through the v1.7 guard. Patching `type(os.environ)`'s `__getitem__`/`__contains__`/`get`/`keys`/`values`/`items`/`__len__` closes all of them — executed and confirmed).
  - **`numpy.random`:** the harness patches **every public callable in `numpy.random`, at *both* the top-level module AND each private submodule that independently binds the same class** — `numpy.random._pcg64.PCG64`, `numpy.random._generator.Generator`, `numpy.random.bit_generator.SeedSequence`, `numpy.random._mt19937.MT19937`, `numpy.random._philox.Philox`, `numpy.random._sfc64.SFC64` (design-review-008 C3 repair, executed: Round 7 patched only the top-level `numpy.random.X` names; numpy's own `__init__.py` imports these classes from their private submodules, which keep their *own* binding of the identical class object untouched by a top-level rebind — an ordinary `import numpy.random._pcg64 as _p; _p.PCG64()` bypassed the v1.7 guard entirely, with no reflection and no `ctypes` — patching both levels closes it, executed and confirmed). Patching only the two named constructors (or swapping the hidden `mtrand._rand` singleton) also leaves `np.random.normal()`/`uniform()` live for the same reason (Round 7); numpy's public + private random API is a *finite, documented, stable* contract, unlike the open reflection graph.
  - **`builtins.open`/`io.open`, `time`/`datetime` entry points, `socket`, `subprocess`.**
  - **`numpy.datetime64`** (numpy's C clock — Round 6 executed `np.datetime64('now')` reading the real wall clock while Python's `time` was guarded). **This one guard is a module-level rebind (`numpy.datetime64 = wrapper`), not a mutation — disclosed honestly, not claimed otherwise (design-review-008 C2 repair): `numpy.datetime64` is an immutable C type (`setattr(np.datetime64, '__new__', raise)` raises `TypeError: cannot set '__new__' attribute of immutable type`), so no attribute of the type or any instance can be mutated in place; a rebind is the only mechanism Python allows for this one guard, and it carries the rebind's known limitation — a reference captured before the harness installs (`from numpy import datetime64 as captured` in a module imported earlier in the call graph) bypasses it. This is a genuinely different mechanism from every other guard in this list, which is why it is called out separately rather than folded into the umbrella "mutates in place" claim.**

  Teardown restores every saved attribute/method in a `finally`. TC-JU12-02 injects the `__globals__`-routed `os` read and TC-JU12-03 the `numpy.datetime64` read to prove the guard fires on both (it does).

  **What this control does NOT catch — disclosed, not hidden (design-review-008 narrowed this list — Round 8 execution showed the top-level-plus-submodule `numpy.random` patch actually closes the "unseeded `Generator(PCG64())` reaches `getrandom()`" route Round 7 had disclosed as uncatchable: `PCG64`/`Generator`/`SeedSequence` construction now raises at either binding, so the guard fires before any entropy syscall happens; the residual is smaller than previously stated, not larger).** The guarded set is still a *finite, hand-maintained enumeration of the known ambient API surface*, and no finite enumeration closes Python's reflection/syscall graph — the same reason the static AST gate is lint, one layer down. Two routes remain, both requiring deliberate intent: (a) **`ctypes`, already resident in `sys.modules` the moment numpy imports** — a `ctypes.CDLL(None)` call reaches raw syscalls (wall-clock, filesystem) with no import statement to see and no Python object to mutate; (b) **any capability bound to a local name before the harness installs**, beyond the specific holders enumerated above (the one instance of this the guard cannot close by construction is `numpy.datetime64`'s rebind, disclosed above). Both are excluded by the threat model (the judge author is not the adversary). Any *accidental* slip that still produces run-to-run variation — including through routes this enumeration failed to name — is caught **empirically by the ten-run byte-identity gate (TC-NF1-01), which is the load-bearing reproducibility control, and which design-review-008 pinned to run its ten repetitions across *separate processes*** (not merely ten in-process calls, which would miss a value that is stable within one process but varies across fresh ones — design-review-008 C9 executed exactly this phantom-gate scenario). The purity harness is the fast, human-readable tripwire that names *which* ambient call was made when byte-identity would otherwise just report "outputs differ." JU-12 is delivered by the harness **and** byte-identity together, with the residual named; it is not delivered by the harness alone, and this spec does not claim it is.
- **The static AST gate (ADR-003's allowlist, TC-NF6-01..) is fast-feedback lint, not proof.** It catches the honest mistakes and casual evasions at commit time, cheaply, before the slower runtime harness runs — a genuine convenience. It is explicitly **not** a security boundary and the spec no longer claims it closes "all realistic indirection routes": Python reflection defeats any such gate, disclosed rather than implied away (LANGSEC's own point).
- **Threat model, stated (Anderson: name the adversary).** The judge author is *not* the adversary — the author writes the judge. The property these controls protect is **accidental impurity that would break reproducibility (NF-1) or blindness (JU-1)**: a stray `time.time()`, a debug `print` to a file, a `numpy.random` call that varies between runs. A determined author deliberately smuggling ambient state past the runtime harness through reflection is out of scope — it is self-sabotage of one's own instrument, not a threat the instrument defends against, and no in-process control in Python could stop it anyway (design-review-007/008 executed the proof: `ctypes` is already resident via numpy and reaches raw syscalls with no import to see, and a value captured before the harness installs — `numpy.datetime64`'s one disclosed rebind exception — bypasses any object-mutation harness by construction). This is why the purity harness's claim is deliberately *best-effort over the known API surface*, not completeness, and why the **empirical byte-identity gate (TC-NF1-01) is the actual guarantee** for the accidental case: an accidental ambient read or `numpy.random` slip produces run-to-run variation, which byte-identity flags — across separate processes, not merely within one — even though the harness did not name it. The harness's value is *diagnostic speed and legibility* (it says which ambient call fired), not completeness. Worlds and models get *empirical* enforcement only — the byte-identity tests (TC-WD7-01/02, TC-MU8-01, TC-NF1-01/02) plus code review — which catches an ambient read that varies between runs but not one stable on the test machine; that asymmetry is deliberate (JU-12 names the judge as the load-bearing boundary, not worlds/models).
4. **Canonical serialization.** One shared serializer produces every machine-readable artefact — including `wmj/reporting/writer.py`'s write of `out/verdicts/*.json` and `run-manifest.json` (design-review-008 C8 repair — Round 8 found this ownership contradicted across three documents, one contradicting itself: cross-cutting/judge said the harness writes `out/` directly, reporting's own §4 assigned the write to `wmj/reporting/writer.py`, reporting's own §6 said the harness writes the manifest, and architecture-overview's container diagram showed exactly one path into `out/`, `[reporting]───▶[out/]`, with no harness→out/ edge at all. **Decided, written once, cited everywhere: `wmj/reporting/writer.py` is the sole writer of every artefact under `out/`, using this serializer; the harness assembles `JudgedResult` envelopes and `package_versions` and hands both to reporting, which never computes a metric of its own but does own the write call — this matches the container diagram exactly, so no diagram change was needed.**) — as JSON with sorted keys, UTF-8, `\n` newlines, no trailing whitespace, arrays as nested lists, no timestamps or hostnames anywhere in the payload. **Float formatting, the mechanism pinned, not just the outcome (design-review-008 I7 repair — Round 8 executed the gap: `repr()` on a raw NumPy scalar under NumPy ≥2.0, the version this project's own review environment runs, returns `np.float64(0.031)`, which is not valid JSON — NEP 51 changed numpy's `__repr__`; a hand-rolled implementation of the old "rendered with `repr`" wording breaks outright):** every array is converted with `.tolist()` before it reaches the serializer (confirmed: `.tolist()`'s elements are native Python `float`, immune to NEP 51), and `json.dumps(obj, sort_keys=True)` is the **only** call that renders a float to text anywhere in this pipeline — never a manual `repr()` call on a value that might still be a NumPy scalar. `json.dumps` itself is safe because its C encoder formats the underlying double directly and never calls `__repr__`. Any `Verdict` field is asserted finite before serialization (`json.dumps` renders `inf` as the non-standard token `Infinity`, which `repr(float('inf'))` would not — a second, narrower divergence between the two that non-finite metrics would otherwise expose). NF-1's ten-run byte comparison (TC-NF1-01) compares these bytes, run across separate processes (design-review-008 C9).

**Options considered:** (a) tolerance-based comparison instead of byte identity — rejected: NF-1 explicitly demands byte identity, and tolerances rot; (b) hash-based comparison of floats at reduced precision — rejected for the same reason; (c) the four rules above — accepted.

**Consequences:** Every function that needs randomness takes a `Generator` parameter (visible in every signature — this is a feature, not noise). Cross-*platform* identity (e.g. x86 vs ARM) is explicitly out of scope, matching NF-1's "machines of the same platform" wording; the verdict record states the platform.

## ADR-003 — Project structure: four packages plus a harness, judge imports nothing

**Decision:** A `src`-layout Python package `wmj` with five sub-packages: `wmj.worlds`, `wmj.models`, `wmj.judge`, `wmj.reporting`, `wmj.harness`. The judge imports only the standard library and NumPy — never the other `wmj` packages. The harness is the only package that imports everything.

**Status:** Accepted.

**Context:** NF-6 (separable layers, judge imports nothing from the others), JU-12 (pure judge), MU-9 (new model touches nothing but its own file), JU-1 (judge input structurally cannot carry identity). [Requirement: NF-6, JU-12, MU-9, JU-1] [Test: TC-NF6-01..04, TC-NF6-06, TC-NF6-07, TC-NF6-08, TC-NF6-09, TC-JU1-01, TC-MU9-01, TC-MU9-02, TC-MU9-03]

**Layout:**

```
wmj/
  worlds/        # Domain 1: LV + pendulum, integrator, divergence, regions, tasks
  models/        # Domain 2: baselines, fixtures, two unrigged models, training
  judge/         # Domain 3: pure functions state → verdict; imports stdlib + numpy ONLY
  reporting/     # Domain 4: charts, captions, verdict file writer
  harness/       # orchestration: seeds, data flow, pre-registration checks, CLI
tests/           # mirrors the package layout; plus tests/gates/ for the enforced gates
prereg/          # committed-before-judging artefacts: recipe, margins, thresholds (MU-6, JU-11)
out/             # generated: verdicts + charts (gitignored except published results)
```

**How the structure enforces the requirements rather than promising them:**
- `tests/gates/test_import_graph.py` walks `wmj.judge`'s AST. **Design-review-004 restructure — from denylist to allowlist, with an executable fixture corpus as the gate's final authority.** Four review rounds established the pattern: every enumerated denylist of "bad shapes" was evaded within one round by a shape nobody enumerated (Round 2's dynamic imports, Round 3's aliases and `getattr`, Round 4's `from numpy.random import rand`, `__builtins__`, and `compile`). The repair fixes the *rule*, not the latest instance:
  1. **TC-NF6-01 — the import allowlist.** Any `Import`/`ImportFrom` whose top-level module is not in **`{numpy, math, dataclasses, typing}`** fails. This is judge.md §4's own "nothing else" claim, finally enforced as stated — it subsumes, with nothing left to enumerate, every prior import-shaped check (`wmj.*`, the twelve ambient modules, `importlib`, `random`, `builtins`, and every module nobody thought to list). An allowlist cannot have the omission problem a blocklist has.
  2. **TC-NF6-02 — banned execution-primitive identifiers.** Any occurrence of the identifiers `exec`, `eval`, `compile`, `__import__`, `__builtins__`, `globals`, `vars`, `getattr`, `__globals__`, `__subclasses__`, `__bases__`, `__mro__`, or `__class__` anywhere in the AST — as a `Name` id, an `Attribute` attr, or an import alias — flags the file for review. Design-review-004 simplification: the judge computes deterministic metrics and needs **no randomness at all** (JU-12) — the v1.3 check's Generator/PCG64 exception implied otherwise and forced a name-by-name pattern (`<alias>.random.<name>`) that `from numpy.random import rand` and `import numpy.random as npr` both walked straight past. A total ban has no such pattern to evade.   4. **TC-NF6-04 — the evasion-fixture corpus, the *lint's* regression suite (not a completeness proof).** Every concrete evasion any review round has documented exists as a one-file fixture under `tests/gates/fixtures/`, and the static gate must flag **every** fixture: bare/aliased/from-imports of forbidden modules; `importlib` aliasing; `getattr` indirection; `__builtins__` attribute routes; `exec`/`eval`/`compile` payloads; both `numpy.random` import idioms; identifier rebinding; **and the Round-5 reflection routes — `<fn>.__globals__[...]`, `getattr(<allowlisted>, "__builtins__")[...]`, string-concatenated identifiers, and `().__class__.__base__.__subclasses__()`.** The corpus keeps the lint from regressing on known tricks. **It is explicitly NOT a completeness contract (design-review-005 correction — the v1.4 text called it "the gate's real completeness claim, exactly this, no more," which Round 5 falsified by executing a route outside the corpus):** static analysis of Python cannot be proven complete, so completeness is delivered by the *runtime* purity harness (TC-JU12-01), and this corpus is only the regression floor for the fast lint.
  5. **TC-NF6-05 — superseded (design-review-004).** Its former content (the `<numpy-alias>.random.<name>` attribute pattern) is absorbed and strengthened by TC-NF6-03. The ID is retained as a tombstone per this project's append-only discipline so no ID silently vanishes; it is not an executable case.
  6. **TC-NF6-06 — clean-pass / false-positive guard.** The gate run against the real, legitimate judge source passes — necessary because checks 2 and 3 are deliberately over-broad, and a gate that cries wolf gets disabled.
  7. **TC-NF6-07 — no `models → worlds` import (design-review-005 repair — Round 5 found that "models never import world internals," the claim the entire `WorldContext` ADR was built to satisfy, had no enforcing gate: every existing gate points the other way).** The same AST import-walk applied to every module under `wmj/models/` fails if any of them imports `wmj.worlds` or any `wmj.worlds` submodule. For an `ImportFrom`, the check compares the **joined** `node.module + "." + alias.name` as well as `node.module` itself, so `from wmj.worlds import lv` (module `wmj.worlds`, name `lv`) is caught, not only `import wmj.worlds.lv` (design-review-005 — Round 5 showed the two shapes differ only in which AST field carries the submodule name).   8. **TC-NF6-08 — no `models → harness` import (design-review-007 repair — Round 7 found the invariant the whole `SeedSource`-in-`models.base` redesign depends on, "models never import the harness" (so fixtures can rebuild `direct`'s stream without a `models→harness` import), was asserted as settled fact with no enforcing gate in that direction: TC-NF6-07 checks `models→worlds`, and TC-MU9-01(c) checks the *other four* packages' imports *toward* `wmj.models`, but nothing checked what `wmj/models/*` imports *out* toward `wmj.harness`).** The same AST import-walk over every module under `wmj/models/` fails if any imports `wmj.harness` or any `wmj.harness` submodule, using the identical joined-name check (executed: catches both `import wmj.harness` and `from wmj.harness.trials import build_roster`, passes on `from wmj.models.base import SeedSource, component_key`). This is a build gate, not a convention — but it is **lint, deliberately not proof** (design-review-005). **The runtime purity harness (TC-JU12-01) is the primary purity tripwire** — it executes the judge's full call graph with every *known* ambient capability (filesystem, clock, network, OS, subprocess, RNG) mutated in place, at every level that object is independently bound, to raise on access, so an impure operation through a documented API fails at the point of its **effect**, regardless of the syntax or reflection route that reached that object. But it guards a **finite, enumerated surface**, not "every ambient capability, however reached" — design-review-007/008 executed the two routes it genuinely cannot see (`ctypes` resident via numpy → raw syscalls; a reference captured before the harness installs, `numpy.datetime64`'s disclosed rebind exception being the one guard that structurally admits this). Together they deliver JU-12, with the residual disclosed; the harness alone does not, and this spec does not claim it is "complete." Threat model and full residual: ADR-002 rule 3.

  (a) **Setup, in this order (design-review-005 repair — Round 5 executed two teardown-leak failure modes: restoring `__path__` leaves the stub in `sys.modules`, so a later same-named stub is served the cached module and its `register()` never runs; and a naive registry snapshot-and-restore, if TC-MU9-01 is the first `all_models()` call in the process, snapshots an *empty* registry (the seven real models register lazily on first import) and teardown then wipes them permanently):** first call `all_models()` once to force every real model to register (so the snapshot is the full production registry, never empty); *then* snapshot the registry dict; *then* create the stub module in a pytest `tmp_path` directory and append that directory to `wmj.models.__path__` via monkeypatch; call `importlib.invalidate_caches()`; assert the stub appears in `all_models()`. **Teardown (a `finally`, runs pass or fail) does all three:** restore `wmj.models.__path__`, `_REGISTRY.clear(); _REGISTRY.update(snapshot)` to restore the real roster exactly, **and delete the stub's own key from `sys.modules`** (pop `wmj.models.<stub_name>`) so no cached module survives into a later test.   (b) asserts the stub also appears in the roster built by the **actual production code path** — `wmj.harness.trials`'s roster-construction function invoked directly — proving the harness genuinely delegates to the registry rather than holding a second, separately-maintained list that happens to agree today.   (c) statically verifies, by the same AST **import-allowlist** technique as the NF-6 gate (mechanical, no string-matching to evade), that no module in `wmj/judge`, `wmj/worlds`, `wmj/reporting`, or `wmj/harness` imports any `wmj.models` submodule other than `wmj.models.registry` and `wmj.models.base`. **For an `ImportFrom`, the check compares the joined `node.module + "." + alias.name`, not `node.module` alone (design-review-005 repair — Round 5 showed `from wmj.models import direct` and `from wmj.models import registry` produce the identical `node.module == "wmj.models"`, so a `node.module`-only check waves the forbidden submodule through):** `from wmj.models import direct` joins to `wmj.models.direct` (forbidden), `from wmj.models import registry` joins to `wmj.models.registry` (allowed). Referencing the seven pinned model *name strings* (models spec ADR-M1) as data is explicitly permitted and untouched by this check — names are the sanctioned join keys, imports are the forbidden coupling. TC-MU9-02's injected violation uses the `from wmj.models import <submodule>` shape specifically, so the phantom-gate case exercises the shape a naive implementer would miss. **A second import shape needs its own explicit rule, pinned here (design-review-008 I4 repair — Round 8 executed the gap: a literal join-and-compare implementation false-positives on `from wmj.models.base import SeedSource` — the harness's own sanctioned import — because `node.module` is already `"wmj.models.base"`, and joining it to `alias.name` produces `wmj.models.base.SeedSource`, not literally `wmj.models.base`, so it fails the exact-match allowlist and blocks the import the carve-out exists to permit):** when `node.module` **itself** already equals `wmj.models.registry` or `wmj.models.base` (i.e. an `ImportFrom` naming one of the two allowed submodules directly, importing a *name* from inside it rather than the submodule itself), the check passes on `node.module` alone, without joining — the join step applies only when `node.module` is the bare `wmj.models` package and `alias.name` is what determines which submodule is actually being reached. TC-MU9-01(c)'s own clean-pass fixture (a stand-in for `harness/trials.py`) now includes `from wmj.models.base import SeedSource, component_key` alongside its existing `from wmj.models.registry import all_models`, so this shape has a permanent regression check, not just a one-time observation.
  Registry state is snapshot-and-restored in fixture teardown so no registration leaks between tests. Each of (a), (b), (c) can genuinely fail, and TC-MU9-02's phantom-gate case proves (c) fails when a forbidden import is injected.
- `prereg/` is where MU-6/JU-11 artefacts live; the harness refuses to judge unrigged models unless the committed `prereg/` files predate the run (mechanics in the models and judge specs).
- **Spec/build parity [Requirement: NF-5] (design-review-002 addition; design-review-003 fix traces it to a requirement, a test case, and a build chunk — Round 3 found it was an orphan design element with none of the three, despite the Wiring Matrix claiming completeness):** every generated `specs/*.html` and `requirements/*.html` file carries an HTML comment `<!-- generated-from: {path}.md sha256:{hash} -->` written at generation time. A pre-commit/CI check recomputes the hash of the current `.md` file and fails if it doesn't match the hash embedded in the committed `.html` twin — a byte-level parity check, not a text diff, consistent with this project's NF-1 byte-identity discipline. This does not replace human approval of the `.md`; it only guarantees the `.html` a human might have actually read was generated from that exact `.md`, not a stale or hand-edited copy. Traced to NF-5 ("no claim exceeds what the evidence supports") since a stale `.html` would let an approval and a build silently diverge; covered by TC-NF5-02 (new) and built in P6-C02 alongside the other NF gates.

**Consequences:** Data flows one way: harness pulls from worlds and models, hands plain arrays to the judge, hands the verdict to reporting. The judge cannot even *name* a model. The duplication cost (judge defines its own input dataclasses rather than importing shared types) is the price of NF-6, paid deliberately.

## ADR-004 — Harness orchestration loop and JudgeInput assembly

**Design-review-008 rewrite (design-review-007 opened this ADR to close a gap open since Round 5; design-review-008 found the v1.7 version itself broken — its pseudocode didn't typecheck against the registry contract it cited, its baseline ordering was backwards, and its central choice, one region per `JudgeInput`, contradicted the multi-region `region_labels` design judge §4 and worlds §5 have justified since Round 3, and that ADR-J6's own runtime-budget arithmetic — "200 trials × 2 regions... per model" — already assumed. This version is a whole-model-per-call design, matching what every other part of this spec set already assumed; it is not a second design choice competing with the old one, it is the correction of a mistake.**

**The loop (owned by `wmj/harness/trials.py`, invoked by `wmj run`).** Deterministic, single-threaded, nested in this fixed order (outer to inner). **A `JudgeInput` carries every region a world declares, in one call per model** — never split by region — so `region_labels` genuinely needs its per-trial `{region_name, axis}` shape (worlds §5, judge §4): a single `JudgeInput`'s trials span multiple, distinct regions, exactly what that shape was designed for.

```
for world in sorted(worlds):                        # {lv, pendulum} — sorted-name, ADR-002
    ctx = build_world_context(world)                 # WorldContext, from World.regions()/World.scale
                                                       # (models spec ADR-M1 — one producer, one site)
    train = generate_training_data(world, seeds.rng_for(world, "training", "train-starts"))
    region_names = ["training"] + [r.region_name for r in world.regions().out_regions]  # worlds §4.3
    starts = {r: draw_starts(world, r, seeds.rng_for(world, r, "eval-starts"))          # N=200 per
              for r in region_names}                  # region, PAIRED across models (same seed)

    # Baseline pre-pass — design-review-008 C5: persistence/linear sort LAST in all_models()'s
    # sorted-name order, but every model's JudgeInput needs their predictions, so roll them out
    # first, explicitly, rather than relying on iteration order to happen to produce them in time.
    baseline_preds = {}
    for name in ("persistence", "linear"):            # the two pinned baselines, models ADR-M1
        factory = all_models()[name]
        m = factory(ctx, seeds, train)
        baseline_preds[name] = {r: roll_out(m, world, r, starts[r]) for r in region_names}

    for name, factory in sorted(all_models().items()):  # design-review-008 C4: .items(), not
        if name in baseline_preds:                       # bare iteration — all_models() is a
            preds = baseline_preds[name]                 # dict[str, Factory], iterating it
        else:                                             # yields keys, and Factory IS the
            m = factory(ctx, seeds, train)                # callable, not an object with a
            preds = {r: roll_out(m, world, r, starts[r]) for r in region_names}  # .factory attr

        ji = assemble_judge_input(world, region_names, starts, preds, baseline_preds)
        verdicts[(world, name)] = judge(ji)              # ONE pure call per (model, world) —
                                                            # every region inside, matching
                                                            # region_labels' existing design
    envelopes = [JudgedResult(model_ref, name, is_fixture, verdicts[(world, name)], meta)
                 for model_ref, name in enumerate(sorted(all_models()))]
```

Two invariants the loop must hold, both already required elsewhere and now located in one place:
- **Paired trials (JU-8 / ADR-J6).** The N=200 eval starts for a (world, region) are drawn from `seeds.rng_for(world, region, "eval-starts")` — a function of the region's identity, not of the model — so every model in the roster sees the *same* 200 starts per region (paired comparison). The `"eval-starts"` purpose key keeps them disjoint from training starts (MU-7) and benchmark starts (WD-4), per ADR-002 rule 2.
- **The judge is called once per (model, world) — never once per (model, world, region).** `n_trials` for a given `JudgeInput` is therefore `N × |region_names|` (matching ADR-J6's own "200 × 2 regions" runtime arithmetic, which already assumed this), not `N` alone; `region_labels` is what lets the judge's own metric blocks (`error_vs_horizon.per_region`, `calibration.per_task`, etc.) be populated correctly from one mixed-region array, per judge §5's block×axis table — no separate harness-side collation step exists or is needed, because there is exactly one `Verdict` per (model, world) directly, matching `JudgedResult`'s own "one per (model, world)" contract (Data-Model Overview, below) with no merge step in between.

**Disclosed asymmetry: `worlds` above is a hardcoded literal set, not a registry (design-review-008 I2 — Round 8 found this undisclosed).** `all_models()` auto-discovers every model file under `wmj/models/` (ADR-M1) — adding a model is genuinely one file, isolation-tested (TC-MU9-01). No equivalent `all_worlds()`/`pkgutil`-based discovery exists for `wmj/worlds/`; `worlds` is a fixed `{lv, pendulum}` the harness names directly. This is not a broken promise — MU-9 is worded model-scoped only, and no WD requirement claims world-level one-file extensibility — but it is a real, previously-unnamed asymmetry, named here in the same spirit as ADR-M5's residual risks: adding a third world would need a second file edit (this loop) and a fresh `derive_thresholds.py` run, not the one-file, auto-discovered path a new model gets.

## Error-Handling Conventions

**The rule (McConnell, defensive programming): fail loudly and completely, never partially.** This project's credibility requirements make silent degradation worse than crashing:

1. **Refuse, don't improvise.** Missing baselines → the judge raises `MissingBaselineError`; no verdict is produced (TC-MU2-01). A required verdict field that cannot be computed → the run aborts; no partial record is written (TC-JU9-02). Pre-registration files missing or dated after the run → the harness refuses to judge unrigged models (TC-JU11-02).
2. **Typed exceptions, single module per package.** Each package defines its exceptions in one `errors.py`. Every exception message names what failed, what was expected, and which requirement's gate fired (e.g. `"WD-3 gate: model integrator step 0.02 != world step 0.01"`).
3. **Gates fail the run, not the assertion count.** The enforced gates (integrator match, drift bound, determinism, import graph, prereg timestamps) run both as pytest tests and as startup checks in the harness — a violated gate stops the pipeline before any output is produced.
4. **No `except: pass`, no default fallbacks for configuration.** Absent configuration is an error, per McConnell — a default that masks a missing value would quietly break pre-registration.

## Data-Model Overview

Full schemas live in the domain specs; the shared shapes every package agrees on are fixed here. All arrays are `numpy.float64`; all types are frozen dataclasses (Ramalho: value types as dataclasses).

| Type | Shape | Owner spec | Consumed by |
|---|---|---|---|
| `State` | `float64[d]` — d=2 (LV: prey, predator), d=4 (pendulum: θ₁, θ₂, ω₁, ω₂) | worlds | everyone |
| `Action` | `float64[a]` — a=1 both worlds (cull/restock rate; pivot impulse) | worlds | everyone |
| `Prediction` | `mean: float64[d]`, `spread: float64[d]` — per-dimension mean and standard deviation (the MU-1 fixed uncertainty format; the ensemble's mapping to this format is pre-registered, see models spec) | models | judge |
| `JudgeInput` | arrays only: predictions, spreads, outcomes, `region_labels: [n_trials]` of `{region_name, axis}` (one canonical shape, cited by worlds/models/judge specs alike — design-review-003 fix, see judge spec ADR-J4/§4), divergence curve `[H+1]`, climatology table, task tolerances — defined inside `wmj.judge`, no identity fields, no separate boundary-marker field (a trial's row in the array's trial axis *is* its boundary — design-review fix, see judge spec ADR-J4) | judge | judge |

| `JudgedResult` | the harness-owned envelope `{model_ref, model_name, is_fixture, verdict, meta}` — one per (model, world); wraps a `Verdict` with the identity/metadata facts only the harness holds (design-review addition, judge spec §5); `model_ref` indices follow `all_models()`'s sorted-name contract (models spec ADR-M1), so they are reproducible across machines **within one fixed roster**. **Disclosed limit (design-review-007 I3 — promised in Round 6's remediation plan, written here): `model_ref` is a sorted-position index, so adding a model that sorts earlier shifts every later model's `model_ref` across roster versions. | `WorldContext` | `{world_name, state_dim, action_dim, training_state_box: [d,2], training_action_interval: [a,2], scale: [d]}` — frozen dataclass defined in `wmj.models.base` (deliberate duplication, same pattern as the judge's own input types); constructed **only** by the harness from the world's declared constants, passed identically to every model factory (models spec ADR-M1; `scale` and the `[a,2]` action shape added design-review-005 — the MLP normalises by `scale`, which must arrive through this channel, not a `wmj.worlds` import) | harness (constructs), models (defines type) | every model factory |
| `TrainingData` | `{states: [N, H+1, d], actions: [N, H, a]}` — frozen dataclass in `wmj.models.base`; the world's seeded training trajectories, constructed once per world by the harness and passed to every factory (models spec ADR-M1, design-review-005 — the channel through which a model receives the data it fits to; the interface previously had none) | harness (constructs), models (defines type) | every model factory |
| `SeedSource` | frozen, `wmj.models.base` (with the pinned pure `component_key`); `{run_seed, my_name}` + `rng(*purpose)` / `rng_for(*parts) -> Generator`; content-addressed via `SeedSequence(entropy=[run_seed, *component_key(*parts)])`. **The `Prediction.spread` convention** — one standard deviation per dimension — is the single uncertainty vocabulary of the whole system (MU-1). How a model *derives* its spread is its own business; what it *means* is fixed here and never varies (TC-MU1-01, TC-MU1-02). This settles Open Question 4's format half; the ensemble's spread-mapping rule is settled in the models spec.

## Confidentiality Scan (NF-4) — the forbidden-terms list

**Design-review addition (v1.1); redesigned (v1.2).** Architecture-overview and the implementation guide both referenced "the forbidden-terms scan" and TC-NF4-01 explicitly promised the list would be "declared and kept current in the technical spec" — but no prior spec draft actually declared it. v1.1 declared it, but design-review-002 (Round 2, Panel A) found the v1.1 mechanism self-defeating: its own remediation instruction told a maintainer to write the actual forbidden term into `wmj/harness/confidentiality.py`, a tracked file on a public repository — following the ADR as written would cause the exact NF-4 violation it exists to prevent. Separately, the empty seed list meant the scan always passed vacuously regardless of repository contents. Both are fixed below.

**The mechanism (v1.2): a gitignored local terms file, checked pre-commit, with the gap named honestly.**

- The real, specific forbidden terms — if any are ever identified — live in `wmj/harness/confidentiality_terms.local.txt` (one term per line), which is listed in `.gitignore` and **is never committed**. Following this project's confidentiality rule requires writing a real term only into a file that structurally cannot reach the public repository.
- A committed template, `wmj/harness/confidentiality_terms.example.txt`, ships instead — generic placeholder guidance only ("employer name", "internal team/committee name" as category labels, no actual terms), so a fresh clone has something to copy from without ever seeing a real term.
- `scan_repository()` reads `confidentiality_terms.local.txt` if present, plus the small set of structural pattern classes that are safe to keep generic and committed (e.g., a regex for common internal-only URL/hostname shapes). It walks every tracked file in the working tree (via `git ls-files`, so it naturally excludes `out/` and other gitignored paths), **scans commit-message history** (`git log --format=%B --all --reflog`), and **walks every object in the local object database** (design-review-003 added historical blobs via `git rev-list --objects --all`; design-review-004 repair: `--all` reaches only ref-reachable objects, missing reflog-only content — amended-away commits, deleted branches, dropped stash entries — which are exactly as recoverable via `git cat-file -p <sha>`; the scan now enumerates via **`git cat-file --batch-all-objects --batch`** (design-review-006 repair — Round 6 *executed* the v1.5 command and found `--batch-check` emits only `<sha> <type> <size>` per object and **never any content**, for blobs or commits, so the scan searched nothing and TC-NF4-01 would pass green regardless of what forbidden terms sat in history: `--batch-check` found 0 matches for a planted term, `--batch` found it. The `--batch` form emits each object's full content, which is what the scan greps), which lists **every** object in the database, reachable or not, and searches the content of **both blob and commit objects** — closing the reflog-expired/unreachable channel design-review-005 identified while actually reading content, which the `--batch-check` form design-review-005 wrote could not do). The remaining bound is stated plainly, and more carefully than before (design-review-005): objects already pruned by git's garbage collection are gone from the local database and cannot be scanned. This bounds only *future* local detection — it is **not** a claim that such content was never exposed: a term committed, pushed, then amended away and later gc-pruned *was* published for the window before the force-push (and dangling commits often stay fetchable by SHA on the remote for a period after). The honest statement is that no *local* scan can un-expose an already-pushed object; the scan's job is to stop a term reaching the remote in the first place, which is why the pre-commit layer matters most. Case-insensitive search for each term; fails loudly (per the Error-Handling Conventions above) listing every match's file/commit/blob and location if any are found.
- **The precondition that replaces the vacuous-pass gap:** if `confidentiality_terms.local.txt` does not exist or is empty, the **pre-commit hook** fails loudly with an instructional message ("no local confidentiality terms configured — see `confidentiality_terms.example.txt`") rather than silently reporting a clean scan. An unconfigured scan is now a stop, not a false green.
- **The hook's installation path, named explicitly (design-review-003 fix — Round 3 found three independent panels flagging that no document ever specified how a pre-commit hook reaches `.git/hooks/`, which `git clone` never populates):** the hook script is committed and tracked at `.githooks/pre-commit` (a normal file, unlike `.git/hooks/`, which is versioned like any other repository content). The repository's one-time setup step — documented in the README and named explicitly in this ADR rather than left to be inferred — is `git config core.hooksPath .githooks`, run once per clone. This makes the hook's existence auditable (it's a file in the repository anyone can read) even though its *activation* still depends on that one command having been run.
- **There are exactly two enforcement layers, both local — no others exist (design-review-004 repair: v1.3's disclosure described a "CI re-run" of this scan as an existing backstop, but no CI system is built, configured, or listed anywhere in this design, and architecture-overview §1's own System Context states there are no external systems beyond git itself; the phantom layer is deleted rather than built, since building it would contradict the architecture):** (1) the pre-commit hook, and (2) `python -m wmj run`/`verify`'s startup gates (P6-C02), which re-run the full scan — working tree, commit messages, all objects — on every execution, independent of whether the hook was ever installed. **The startup gates additionally verify `git config core.hooksPath` resolves to `.githooks` and fail with an instructional message if it doesn't** (design-review-004 addition — Round 4 found a pre-existing `core.hooksPath` from unrelated tooling would silently defeat the hook with no visible signal; this converts that silent failure into a loud one at the first `wmj run`).
- **The residual gap, named rather than hidden (matching models spec ADR-M5's disclosure pattern; widened by design-review-005 — Round 5 found the enumeration framed every bypass as a *lapse in a local workflow*, understating routine paths that never touch either layer):** neither local layer fires when a commit is made *without a local hook-running checkout at all* — a direct edit or PR-merge through GitHub's web UI, or a commit from a libgit2-based GUI client that skips `core.hooksPath` by default (not only the explicit `git commit --no-verify`); a fresh clone that never runs the one-time `git config` step and never runs `wmj run`; or any push made between a scan and the next `wmj run`. There is **no pre-push layer** — both layers are commit-time or run-time, not push-time — so a `--no-verify` (or web-UI) commit pushed without an intervening `wmj run` reaches the remote unscanned. No technical mechanism in a single-author, no-server-side-review project fully closes these without infrastructure this project's own architecture deliberately excludes; all of it is disclosed, not presented as solved. The one process discipline that actually shrinks the surface — run `wmj run`/`verify` (which re-scans everything) before every push — is named in the README as the recommended habit, since it is the only thing that covers the web-UI and `--no-verify` paths the hook cannot.

**Maintenance:** `confidentiality_terms.local.txt` is append-only by the same git-hygiene discipline as `prereg/` in spirit (though, being gitignored, its own history isn't tracked by git — the discipline is a personal-process one, not a mechanical one, and is named as such).

## Development Conventions

- **TDD, strictly (Beck, via test-cases.md):** each build chunk starts from its named TC-IDs; the failing test precedes the code. Tests are co-located per package under `tests/`, named for behaviour (`test_wd3_gate_fails_on_step_size_mismatch`, per Metz).
- **Type hints on every public signature** (Ramalho); `from __future__ import annotations` throughout. No runtime type-checking dependency — hints are documentation and IDE fuel, per NF-3.
- **Plain-English docstrings carry the "In plain words" discipline (NF-5 territory):** every public module and function docstring says what it does in ordinary language. A reader of the source meets the same voice as a reader of the requirements.
- **Naming:** requirement IDs appear in gate-test names and error messages, so a failing check names the requirement it protects.
- **No `__init__.py` re-export mazes:** import paths mirror the layout; `wmj.judge.calibration` is where calibration lives.
- **Git hygiene:** `out/` artefacts are regenerated, never hand-edited; `prereg/` files are append-only once committed (their history *is* the pre-registration evidence).
