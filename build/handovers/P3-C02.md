## What this chunk delivers

In plain words: the **registry** — the single table that maps a model's
name to the function that builds it. A model exists to the harness only if
it is in this table, and adding one is one file that calls `register(...)`
at import time (MU-9's one-file extensibility). This chunk also **wires the
two baselines into it**.

Most of what the implementation guide lists for P3-C02 — the baselines'
behaviour, both spread fits (`ddof=1`, guarded), `reset()` isolation, the
`is_baseline`/`is_fixture` flags, and TC-MU1-01/02/03 — was already built
across P1-C02, P2-C05, and the Round-9 A8 fix. The genuine new surface here
is the registry module and the two `register(...)` calls.

- `src/wmj/models/registry.py` (NEW):
  - `Factory` — a loose `Callable[..., object]` alias for
    `factory(ctx, seeds, training) -> Model` (the concrete types live in
    `wmj.models.base`; a name→factory table needs none of them).
  - `DuplicateModelError(WmjError)` — a name collision fails loudly; the
    first registration is never silently overwritten.
  - `register(name, factory)` — module-level call at import time (ADR-M1).
  - `all_models() -> dict[str, Factory]` — the registered factories,
    name-keyed, in **sorted-name order** (the pinned contract — `model_ref`
    derives from it), a fresh dict each call.
- `src/wmj/models/baselines.py` — two module-level registrations at import
  time: `register("persistence", persistence_factory)`,
  `register("linear", linear_factory)`.
- `tests/unit/models/test_registry.py` (NEW, 7 tests) — sorted-name order,
  duplicate-name phantom-gate, fresh-dict-per-call, both baselines
  registered under their names, with a snapshot/restore fixture so
  throwaway-name tests never corrupt the real roster.

## Scope carve — discovery deferred to P6-C01 (and backlog A11)

Per the implementation guide's wiring matrix, `wmj.models.registry` is
"consumed by `harness.trials` discovery … wired at P6-C01," and
**TC-MU9-01** (the auto-discovery + isolation acceptance test) is a P6-C01
test. So this chunk builds the **registration substrate only**. The
`importlib`/`pkgutil` **auto-discovery** half of `all_models()` is built at
P6-C01, where it is first consumed and testable.

This deferral also resolves, without weakening any gate, a genuine spec
contradiction found this chunk: cross-cutting ADR-003 specifies discovery
via `importlib`/`pkgutil`, but the *same* ADR-003's models import-allowlist
says the models package may import "nothing else, in any direction" and
omits both. Building discovery now would force a carve-out in a load-bearing
security gate for a mechanism nothing consumes until P6-C01. Recorded as
**backlog A11** (the A4-class: allowlist text falsified by a
legitimately-required import), with a recommended registry-scoped carve-out
for P6-C01 to implement and a design-review round to ratify. `all_models()`
is honest about the deferral — its docstring says it returns the models
registered so far and does not claim to discover.
