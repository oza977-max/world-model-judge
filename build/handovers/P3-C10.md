# Handover: P3-C10 — The one-time freeze

**In plain words:** the judge may only grade the two practice models if the
recipe, the written prediction and the pass/fail thresholds were *locked
once, before the run, and have not moved by a single byte*. This chunk is the
check that decides that. The lock is the one commit that added the small file
`prereg/FREEZE`; the check finds it in git history (nobody types it in),
refuses if there was ever a second lock or a lock that was lifted, refuses if
any locked file differs from its locked bytes, refuses if the lock does not
precede the run, and hands back the lock's commit id so every verdict can say
which locked version it was judged against. It was attacked by six independent
reviewers; the final one found no way to get a false "locked" certificate and
no way to make git run attacker-supplied code.

## What the check refuses (each is a built-and-tested scenario)
- not frozen yet / frozen twice / frozen then lifted (counted over every local ref except `refs/stash` and `refs/replace/*`, and through merge commits — by presence in each commit's tree, not by `git log --diff-filter`, which cannot see merges);
- a locked file edited, deleted, a symlink, in a symlinked directory, a directory at the freeze, uncommitted, a different line ending, a trailing space/BOM/newline;
- the freeze not strictly before the run; the recipe's kick settings not equal to the worlds' own;
- an unrigged model not declared as a whole token in the recipe and prediction;
- a history git cannot vouch for: shallow clone, grafts file, partial clone, `git fsck` failure, top-level mismatch, forged objects/commit-graph/replace refs.
- Git runs with ambient `GIT_*` dropped, replace refs and the commit-graph off, no lazy fetch, no repo-supplied program (fsmonitor, hooks, textconv/clean filters never run; `git status` is never used).

The count did not fall from pass 3 to pass 5 because the reviewers moved from "find a way to cheat the lock" (passes 1–3 found real attack routes, all fixed) to systematic mutation testing of the *tests*; passes 4 and 5 found no route to a false certificate and no code-execution route — every Important finding was a rule the code enforced correctly but no test pinned. - Pass 3: **Critical** — a partial clone made git run the repo's own `remote.*.uploadpack` program mid-check (now refused outright, lazy fetch also off); the recipe/prediction text is now decoded from the bytes that were compared, not re-read; "one freeze ever" was counted only along HEAD's ancestry (now every ref); two untested rules pinned.
- Pass 4: tests for multi-model entries, merge second parents, tag/remote/notes refs; stale docs; refusal now names the commits.
- Pass 5: tests for name-token boundaries, linked-worktree grafts, any non-zero fsck exit, relative/symlinked repo paths; certified paths must be blobs (a directory at the freeze was accepted).
- Pass 6: 0. Minor, fixed: `i18n.logOutputEncoding` in a repo's config could crash the timestamp read (now pinned); fsck failure message names the dangling-remote-HEAD case; tests for a delete through a non-first parent, an uncommitted revert to the frozen bytes, and an exact margin tie.

**Redundant defences (survive single mutation by design):** `GIT_NO_LAZY_FETCH` (the partial-clone refusal also stops it); `GIT_NO_REPLACE_OBJECTS` and `core.useReplaceRefs=false` (either alone suffices; removing both is killed); the unreachable missing-parent check (commented); `core.hooksPath` pin (no command used runs a hook).

## Known minor, not fixed (owner/next-review)
- A repository owned by another user is refused by git ("dubious ownership") and the global-config switch-off means git's own hint cannot help; hits CI/container mounts.
- A squash-merged feature branch whose old ref survives (e.g. `origin/feature`) causes "added 2 times" — the message now names the commits and suggests deleting the stale ref.
- HEAD-versus-working-tree leniency is two-way for CRLF-only differences (the judged bytes are still the frozen bytes).
- `read_matching_margin` reads from disk and accepts `nan`/`inf` (outside the freeze threat model).

## Deviations from Spec
- The freeze count is by tree presence over all refs, not `git log --diff-filter` (backlog **A18**; spec text not edited).
