# Handover: P6-C01a — The orchestration loop (`harness/trials.py`)

**In plain words:** the loop that runs the whole test is built. For each world it does seven things, in a fixed order:
1. It makes the training data once, and every model gets the same data.
2. It draws the test starting points per region. These are the same for every model, and none of them may be a training start.
3. It steps the true world once from each point, with no kick, and grading starts there (the owner's warm start).
4. It runs the true world on from those starts, with each trial's own seeded kicks.
5. It runs the two simple baselines first, then every other model. Each model is shown the warm-up step, then given the true start, then fed its own guesses step by step.
6. It hands everything, in the judge's units, to the judge, once per model and world, with every region in that one call.
7. It wraps each verdict in its envelope: the model's name, its fixture label, the run details and its action-lever check.

It writes nothing: the writer (P5-C04) does that, and `wmj run` (P6-C01b) joins the two. The tests never measure `direct`, `ensemble` or a fixture built on direct's trained core. They use a stand-in roster: the real baselines, the real fixture classes wrapped round a stand-in core, and test-only models.

- Free-running and the warm start, checked step by step:
  - the warm-up gets the drawn point and a zero action;
  - step 1 gets the true start;
  - later steps get the model's own guesses and the trial's own kicks;
  - the recorded error bar is the one stated for that step;
  - batched and one-at-a-time rollouts are bit-identical;
  - linear now carries on along the warm step.
- Units (A30) against independent rebuilds:
  - outcomes, spreads, the hedge threshold and the climatology tables are divided by the scale;
  - bins are measured from raw true states at every step;
  - the baselines are not swapped;
  - `dt`, the agreement mark, the tasks and the divergence curves match their sources.
- Seeds: starts from `"eval-starts"`, kicks from `"eval-kicks"` (never the training kicks), each factory gets `SeedSource(run_seed, name)`, and the action check uses the run seed.
- Envelopes:
  - each verdict equals the judge's answer on its own model's input;
  - world-by-world order, independent of the order the roster is given in;
  - each envelope has its own copy of `meta`;
  - the real writer accepts them and writes them.
- Refusals before any work:
  - a missing baseline;
  - a pinned baseline that does not declare itself one;
  - model flags that are missing or not `bool`;
  - `meta` keys, seed or text fields;
  - `bands.n` ≠ N;
  - a hedge threshold of the wrong length or a missing world;
  - bad `RunConfig` sizes.
- Rollout guards:
  - shared arrays are read-only, so a model writing into its kicks fails instead of changing later models' trials;
  - a model writing into its own state cannot change its recorded forecast;
  - a non-forecast answer from `predict` or `predict_batch` is refused clearly.
- Production defaults are pinned (200, 64, 50, 20,000, 16, 50, 16; horizons 700 / 5,000).
- Two runs are identical.
