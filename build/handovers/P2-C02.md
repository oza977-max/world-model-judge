# P2-C02 — Pendulum full — Handover

**Status:** Complete. 120/120 tests green.

## What this chunk delivers

In plain words: the second of the project's two worlds now exists —
two rigid links swinging under gravity, chaotic once nudged far
enough, advanced by the exact same shared integrator LV uses. Its
whole point in this project is to be the world where the model is
*allowed* to be wrong for reasons that have nothing to do with a bug:
chaos, not incompetence, is what limits how far ahead a prediction can
be trusted here.

- `src/wmj/worlds/pendulum.py` — the double pendulum world: the
  design-review-002-corrected equations of motion, total mechanical
  energy (the conserved quantity), regions (`training` /
  `out-near-inverted`), tasks (`dp-control` τ=0.05, `dp-planning`
  τ=0.30), unwrapped angles, and the same abort-loudly error handling
  as `lv.py` (`ActionRangeError` for |u|>2.0; no state-floor concept
  applies to angles/velocities, so no `StateFloorClampError` path
  exists here — correctly absent, not silently missing).
- `tests/unit/worlds/test_pendulum.py` — TC-WD1-01 (freshly
  hand-verified reference, see below), TC-WD2-01, action-range and
  region-spec guard tests (both failure paths exercised directly).
- `tests/unit/worlds/test_wd7.py` + two subprocess scripts
  (`_pendulum_rollout_pure.py`, `_pendulum_rollout_impure.py`) —
  TC-WD7-01 (byte-identical trajectories across genuinely separate
  processes) and TC-WD7-02 (negative — an injected unseeded
  `numpy.random` call breaks byte-identity).

## Scope decision: a fresh TC-WD1-01 reference value

worlds.md's own §8 explicitly flags its pinned pendulum reference
value as stale: "must be (re-)computed from the design-review-002-
corrected EOM... any value computed from the v1.1 formula's `2·m`
coefficients is wrong and must not be reused." No recomputed value
was recorded anywhere in the spec suite, so this chunk computed one —
same discipline as P1-C02 did for LV — via an independent, plain-
Python (no NumPy) RK4 implementation, from `(0.1, 0.1, 0.0, 0.0)`,
`u=0`, `dt=0.002`. Independently re-derived a second time during
review by a fresh implementation (not copied from either the source
or the test): matched to all 16 printed significant digits.
