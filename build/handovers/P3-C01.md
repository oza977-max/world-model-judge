## What this chunk delivers

In plain words: the small neural network, written out by hand in NumPy
with no deep-learning library, that both un-rigged models under test
(the "direct" one and the five-member "ensemble") are built on. Because
it is hand-written, every number it produces is ours to explain and ours
to reproduce exactly. This chunk builds the **core only** — the shared
architecture, the optimiser, and the check that proves the hand-written
backprop is correct. The task-specific heads and losses arrive at
P3-C03 (direct: error-bar output + Gaussian-NLL training) and P3-C04
(ensemble: mean-only members), which import this module.

The load-bearing piece is the **gradient check**: a hand-written
backprop is worthless unless it agrees with finite differences, so the
module ships a checker that compares the two and refuses loudly if they
disagree. Per models §8's pre-TC discipline (Beck's failing-test-first),
that check is the module's own first test — written and Red before the
`backward` it validates existed.

- `src/wmj/models/mlp.py`:
  - `MLP(layer_sizes, rng)` — `W ~ U(-1/√fan_in, 1/√fan_in)`, biases 0,
    every draw from the passed `Generator` (ADR-002). Tanh on every
    hidden layer, **linear output** (outputs are Δmean / logσ / mean —
    unbounded). Rejects `< 2` layer sizes and any zero/negative-width
    layer with `MLPArchitectureError`.
  - `forward(X) -> (output, cache)` — cache holds each layer's input and
    the hidden tanh activations, so `backward` recomputes nothing.
  - `backward(cache, d_output) -> [(dW, db), ...]` — loss-agnostic
    reverse-mode gradients.
  - `Adam(shapes, lr=1e-3, β₁=0.9, β₂=0.999, ε=1e-8)` — pinned ADR-M3
    hyperparameters; `step` updates weights in place.
  - `gradient_check(mlp, X, loss_and_grad, *, epsilon=1e-5,
    tolerance=1e-5) -> float` — max relative error between analytic
    backprop and central finite differences; raises `GradientCheckError`
    if it exceeds tolerance or if any gradient/loss is non-finite.
  - `MLPArchitectureError`, `GradientCheckError` (subclass `WmjError`).
  - Constant `GRADIENT_SCALE_FLOOR = 1e-3` (the metric floor, see A10).
- `tests/unit/models/test_mlp.py` — 16 tests. Gradient-check-first
  ordering; a phantom-gate proving the check can fail; NaN/inf guards;
  weight-restore-on-error; determinism; init scaling; Adam convergence;
  a real-ADR-M3-architecture regression test; a single-row TDD-3 variant.

## Deviations from the prompt — recorded as spec-correction A10

The prompt (and models §8) pinned the gradient check at **`1e-6`
relative** and proposed `epsilon=1e-6`. Executing the check against the
**real** ADR-M3 architecture (2 hidden × 64) — which no toy net exposes
— falsified both. Full detail, executed evidence, and the decision put
to Round 10 design review are in `build/spec-corrections-backlog.md`,
item **A10**. In brief:

1. **The naive relative-error metric misreports correct backprop.**
   `|a−num| / (|a|+|num|)` (CS231n) blows up for a parameter whose true
   gradient is near zero — on `[5,64,64,4]` seed 15 a weight whose
   gradient is `2.6e-8` (analytic and numeric agreeing to four
   significant figures) reads `1.76e-4`, purely from dividing a `~1e-11`
   absolute difference by a near-zero denominator. **Fix:** floor the
   denominator at `GRADIENT_SCALE_FLOOR × (network's largest gradient)`.
   Scale-invariant (loss ×1000 leaves every reading unchanged). Under the
   floored metric the worst of a 240-net sweep (both worlds' real I/O
   shapes, 60 seeds each) falls from `1.76e-4` to **`3.6e-7`**.
2. **`1e-6` is too tight even with the metric fixed.** A *correct*
   central-difference check on a 3-weight-layer net floors at a few
   `1e-7` on float64 noise alone (240-net worst `3.6e-7`). `1e-6` leaves
   ~3× margin — inadequate for a never-flake gate, especially on trained
   nets downstream. **Fix:** default `tolerance=1e-5` (~30× margin over
   the noise floor; still four orders of magnitude below a real bug — the
   phantom-gate ×1.5 corruption reads `0.2`). `epsilon` set to `1e-5`,
   the float64 U-curve minimum (executed: a 4-16-16-3 net reads `4.2e-8`
   at `1e-5`, `3.1e-7` at `1e-6`, `2.6e-6` at `1e-7`).

The spec documents are **not** edited (a build chunk editing a reviewed
spec to match its own code is the goalpost-moving MU-6/JU-11 police).
The spec text stands at `1e-6`; the code carries the correction and A10
asks Round 10 to ratify both the floor and the tolerance, or prefer a
numpy-`allclose`-style combined criterion.

**Disclosed tradeoff of the floor** (raised by the independent review,
stated in the `gradient_check` docstring and A10): holding a
sub-0.1%-of-peak parameter to absolute agreement gives up sensitivity to
a backprop bug *localised to such a near-dead unit*. Judged acceptable
(such a parameter is negligible to the optimisation step; a structural
formula bug corrupts the peak parameters too and is caught there), but a
genuine blind spot Round 10 owns.

## Review passes (Hard Gate 3, Phase 2)

**Pass 1** (1 Critical, 6 Important, 5 Minor):
- **Critical — silent NaN via builtin `max()`.** Python's `max()`
  discards a NaN that is not its first argument (every `>` comparison
  against NaN is False), so a NaN gradient could pass the check and be
  reported as verified — the exact failure the module exists to prevent.
  **Fixed:** explicit `np.isfinite` guard on every analytic gradient
  (raises before the FD loop) + an in-loop guard raising if any `rel` is
  non-finite. Two regression tests added (NaN analytic; non-finite FD
  loss).
- **Important — the floor can mask a bug on near-dead units.** Not
  removed (it is the point of the floor) but **disclosed** in docstring
  + A10, and the alternative flagged to Round 10.
- **Important — backward recomputed pre-activations from live weights.**
  **Fixed:** `forward` now caches the tanh activations; `backward` reads
  them, so it no longer recomputes from weights. (The one inherent
  live-weight read, `d_pre @ W.T`, remains and is correctly documented as
  the forward→backward→step ordering contract — see the note to
  P3-C03/C04 below.)
- **Important — forward docstring claimed a cache it didn't hold.**
  **Fixed:** docstring now matches `{"inputs", "hidden_outputs"}`.
- **Important — no try/finally restore in gradient_check.** **Fixed:**
  perturb→measure→restore is wrapped in try/finally; a regression test
  proves a mid-sweep exception leaves every weight unchanged.
- **Important — `param.ravel()` aliasing assumption.** **Fixed:**
  switched to `np.ndindex(param.shape)` indexing the live array, which
  always writes back regardless of contiguity.
- **Important (test) — no NaN/inf regression test.** **Fixed** (the two
  tests above).
- Five Minors: `_b` misleading name (**resolved** — the cache change
  removed its only use, so the underscore is now accurate); `1e-12` floor
  not scale-free (**docstring softened**); a `3.6e-7` figure appearing in
  two roles (**re-measured; the epsilon example now cites `4.2e-8`**);
  epsilon/tolerance both `1e-5` coincidence and no epsilon validation
  (**epsilon>0 guard added**; the coincidence is documented per-constant).

**Pass 2** (0 Critical, 0 Important, 2 Minor): all six pass-1 fixes

## Note to P3-C03 / P3-C04 (the training-loop authors)

**Ordering contract:** per training iteration call `forward`, then
`backward`, then `Adam.step` — in that order. `backward` propagates the
gradient through each layer's *current* weight matrix (`d_pre @ W.T`), so
a weight updated between forward and backward silently corrupts the
gradient (no exception). This is standard backprop discipline and is
stated in `backward`'s docstring; it is inherent, not a defect. Both
training chunks gradient-check on real, normalised training inputs (the
regime the FD reference is accurate in) before training begins.
