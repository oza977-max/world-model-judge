# Handover: P3-C06 — Training data + determinism

**In plain words:** every model has to learn from exactly the same homework,
and the harness — not the models — must make that homework. This chunk makes
it. For each world it simulates 2,000 full-length histories with the
occasional kick pushed in, then picks, once and by seeded shuffle, 50,000
"this state plus this push led to that state" examples (exactly 12,500 of
them kicked), sets aside 10,000 more examples that are never trained on, and
chooses 64 training rows for a one-time check of the learning arithmetic.
Every count is read from the frozen recipe. If the world cannot supply enough
examples the build refuses; it never quietly shrinks a number. The same seed
always gives the same bytes.

## Surfaced Requirements — OWNER DECISION D17
- **The held-out set contains almost no kicked examples** (6 LV, 10 pendulum of 10,000), because the 12,500-kick training quota takes most of the kicks the worlds supply. The build-time "held-out error split by kick / non-kick" report (ADR-M3, P3-C03/C04) would rest on those few. Not changed here — it is a pre-freeze recipe revision and the owner's call. Recommended: give the held-out set its own kick quota. See backlog A19 item 2, `REMEMBER.md` D17.
- Related disclosure for the sufficiency test: held-out pairs are pair-level draws, so ≈3.5% (LV) have their successor pair in the M training set (7% in the 2M set); and the M-build and 2M-build held-out sets overlap each other's training sets (361/10,000 LV) — score both models on the 2M build's held-out set (REMEMBER §3 contract).
