# Build Prompt: P3-C06 — Training data + determinism

**In plain words:** before any practice model can learn, someone has to hand
every model the *same* homework. This chunk makes the homework: 2,000 short
simulated histories per world (with the occasional kick pushed in), then one
fixed, seeded pick of 50,000 "this state plus this push led to that state"
examples — exactly 12,500 of them kicked ones, so the models see the lever
often enough to learn it — plus 10,000 examples held back for checking, and
64 examples for a one-time sanity test of the learning arithmetic. The
harness does the picking once; no model is allowed to pick for itself, which
is what keeps the five ensemble members on identical homework and the
fixtures bit-identical copies of `direct`. If the world cannot supply enough
kicked examples the build refuses — it never quietly shrinks the number.

## Spec Excerpt (models §4, ADR-M1 — design-review-010)
- `N_train = 2000` trajectories per world of full horizon from seeded training-region starts (`seeds.rng_for(world, "training", "train-starts")`) with seeded kick sequences (trajectory `i` from `seeds.rng_for(world, "training", "train-kicks", str(i))`, band `"in"`), generated with the batched world step.
- A *pair* is `(state_t, action_t, state_{t+1})`; a *kick pair* has `action_t ≠ 0`. Training set = exactly `kick_pairs` kick pairs (first of a permutation of all kick-pair indices drawn with `"subsample-kick"`; fewer available → `TrainingDataError`, never a silent shrink) plus `M − kick_pairs` non-kick pairs (first of a permutation drawn with `"subsample-nonkick"`).
- Held-out set: `heldout_pairs` pairs from those not selected (first of a permutation drawn with `"heldout"`). Gradient-check batch: first `gradcheck_pairs` of a permutation of the training set drawn with `"gradcheck-batch"`.
- All counts are machine-readable keys in `prereg/recipe.md`. Train/eval split is by starting condition (`"train-starts"` vs `"eval-starts"` seed purposes — independent by construction; the harness also asserts disjointness at run time).
- ADR-M3's fallback `2M` set = the same kick pairs plus the first `2M − kick_pairs` non-kick pairs of the same permutation — so `train_pairs` layout is **kick pairs first, then non-kick pairs in permutation order**, which makes the M-set a prefix of the 2M-set.
