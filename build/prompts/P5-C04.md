# Build Prompt: P5-C04 — Comparison table, results page, writer

**In plain words:** the last reporting chunk. It does three things.

**Chart 4, the comparison table.** It sets out every model on one table. The first columns give its rank on ordinary error, with its skill scores against the two simple baselines beside the rank. The other columns give its trust horizon for each task and region, in steps, world time and natural cycles. Where ordinary error and the judge rank two real models in opposite orders, both rows are marked "⇄ disagree". The caption then says so in one plain sentence. When nothing disagrees, the caption says that plainly instead.

**The results page.** One static web page, openable from disk, shows:
- every chart with its caption;
- near the top, the model card: the judge's ten statements of its own limits, and the list of what was never tested;
- a short methods note saying what the purity check can and cannot catch.

**The writer.** It is the only code that writes the output folder: charts, captions, the verdict files, the run manifest and the page. It checks everything first, so a run with one bad verdict writes nothing at all.

## Pinned decisions

### Chart 4 (owner decision 2026-10-26: strict pairs, no fixtures)
- **One table per world**, one row per model: baselines, the unrigged models and fixtures.
- **Control task:** the task whose `trust_horizons` tolerance is the smallest. Every entry of a task must state the same tolerance; a tie between two tasks' tolerances is refused as ambiguous. The verdict does not carry a task's kind, and tolerance is how the spec defines it ("tight-tolerance control task").
- **Ordinary-error cell:**
  - the source is the `skill.per_task_region` entry at (control task, `training`);
  - the rank is ascending by `crps`, as a competition rank (equal values share a rank);
  - the cell shows the rank, the CRPS, and `vs persistence` and `vs linear` beside it;
  - the header names the source: "{control task}, training, one step".
- **Trust-horizon columns:**
  - one per (task, region) of `trust_horizons.per_task`;
  - tasks in verdict order, with `training` first in each task, then the other regions in verdict order;
  - each cell reads `{steps} steps · {world_time:g} time units · {natural_units}`, with `natural_units` null shown as "—".
- **Disagreement:**
  - **Discordant pair:** two non-fixture models A and B, where `crps` puts A strictly ahead and some horizon column puts B strictly ahead in steps (or the reverse). A tie on either side is not a disagreement.
  - **Marking:** a row is marked `⇄ disagree` and lightly highlighted if it is in at least one discordant pair. Fixture rows are never marked: fixtures are never findings (MU-4).
  - **Caption:** `chart4_caption((A, B))` names the discordant pair closest on ordinary error (smallest ratio of the larger `crps` to the smaller; ties broken by names). The better-`crps` model is named first. With no discordant pair the caption uses the agreement form.
- **Rows** are in error-rank order, with ties broken by name.
- **Fixtures:** fixture rows are prefixed `FIXTURE:`, their name is in the fixture colour, and the row is tinted. A figure with any fixture row carries the fixture sentence above the table.
- **Refuse** (`ComparisonBlockError`) on:
  - mixed worlds, or duplicate model names;
  - different task or region sets across models;
  - a missing (control, training) skill entry;
  - an ambiguous control task;
  - a malformed `skill` or `trust_horizons` block;
  - no non-fixture model.

### Results page
- One static HTML file with no JavaScript.
- Images are referenced by relative path (`charts/...png`), and every text is HTML-escaped. There is no `html` import: escaping is a five-character replace, because the reporting allowlist has no `html`.
- **Order:**
  1. title and a plain-words introduction;
  2. **"What this verdict does not tell you"**: the verdict's `limitations` as a list, and **"Never tested"** with `not_tested`, both verbatim. All envelopes must carry identical lists, or the page is refused;
  3. a **methods note** on the purity check;
  4. per world: the comparison table and its caption, then per model the horizon chart, the calibration chart, and the exception charts, grouped by task with the regions side by side. Every image has its caption beneath it as text.
- **Methods note (TC-JU12-04):** a fixed text in `page.py`, stating the residual as the build actually measured it (backlog A37), neither wider nor narrower:
  - the purity check is a best-effort tripwire, not a guarantee;
  - it cannot see `ctypes`, references captured before it starts, or some of numpy's date-parsing routes to the clock;
  - the load-bearing backstop is the ten-run byte-identity check across separate processes, which holds on the same CPU family and library build (A29).
  - It does not name the closed `getrandom`/`Generator(PCG64())` route.

### Writer
- **`write_run(envelopes, baseline_names, out_dir)`:**
  - `envelopes` covers every (model, world);
  - `baseline_names` names the baseline models, which must be present in every world;
  - `out_dir` must not exist or must be empty.
- **Validate everything first, so nothing is written on any refusal:**
  - each envelope has exactly `{model_ref, model_name, is_fixture, verdict, meta}`;
  - `verdict` passes the judge's door: rebuilt as `Verdict(...)`, its `to_dict()` must equal the input, `schema` included. Otherwise `VerdictSchemaError` (§7);
  - `meta` has exactly `{seed, platform, prereg_commit, thresholds_file}` and is identical across envelopes;
  - every chart block's own checks pass;
  - names are file-safe;
  - each (world, model) appears exactly once.
- **Then write into a sibling staging folder** (`{out_dir.name}.partial`, which must not already exist), and move it into place at the end. A failure part-way leaves no `out/`.
- **Files written:**
  - `verdicts/{world}-{model}.json` is the whole envelope, via `canonical_serialize`;
  - `run-manifest.json` holds `meta`'s four fields plus `package_versions` `{numpy, matplotlib}` from `importlib.metadata.version`;
  - the charts and captions, by the four renderers;
  - `results.html`.

### SVG reproducibility (TC-RP7-02)
Each of the four chart kinds is rendered as SVG in two separate Python processes, and the bytes must be identical.

## TDD Approach
1. **Outside-in first:**
   - Call `write_run` on full envelopes built by the real judge (`assemble_verdict` from every `compute_*` on the judge builder's input), for two models, the two baselines and a fixture.
   - Check the `out/` layout, schema-valid verdict files (TC-RP6-01), the manifest fields, the page's model card above the first chart (TC-RP-CARD-01), the methods note (TC-JU12-04), and the comparison caption (TC-RP4-01/02).
   - Commit red.
2. **Unit tests:** control-task choice; rank ties; discordance (strict, ties, fixtures excluded); caption pair choice; every refusal; HTML escaping; nothing written on any refusal; the staging move.
3. **Realistic variant:** pendulum-like names, three regions, `natural_units` null ("—"), six models including two fixtures, and a 40-character name.
4. Render the table and a screenshot of the page, and **look at both**. Then green, then review.

## Review Criteria
- Computes no judgment. Ranks and the disagreement marker are display comparisons of verdict numbers; no metric is derived.
- Fixtures are never presented as findings.
- The writer is the only code that writes `out/`, and it uses the canonical serializer. Nothing is partly written.
- The page's limitations are verbatim, near the top, legible.
- No pyplot. Imports stay within the reporting allowlist; the gate runs in the same command as every commit.
- Every module has an "In plain words" docstring.
