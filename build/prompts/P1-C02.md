# P1-C02 — MVP slice (user-facing)

## Scope

Per `specs/implementation-guide.md` line 34: minimal LV world (`transition`
+ shared RK4), creates `wmj/models/baselines.py` with persistence + linear
baselines (mean rules + a minimal spread — real spread-fitting is
extended at P2-C05/P3-C02, not this chunk), the harness's minimal
`WorldContext`/`TrainingData` construction, judge `skill.py` (CRPS +
skill), `python -m wmj run --skeleton` writing a `wmj-skeleton/0` JSON
report.

**Spec:** `specs/worlds.md` §4.1 (LV constants), §4.3 (world interface —
`RegionSpec`, `Task`, `World` protocol); `specs/models.md` ADR-M1 (Model
protocol, `WorldContext`/`TrainingData`, factory signature), ADR-M2
(baseline mean/spread rules); `specs/judge.md` ADR-J1 (CRPS closed form,
skill formula).

**Tests:** TC-WD1-01 (LV half — hand-verified no-action reference value),
TC-MU2-02 (supporting — baselines score below a competent model; only
checkable in full once a learned model exists, so this chunk covers the
buildable half: both baselines produce genuinely different, non-trivial
predictions from each other and from raw persistence-of-nothing).

**Acceptance (MVP-1, Hard Gate 9 — no exemption, this is the first
user-facing chunk):** `python -m wmj run --skeleton` runs clean from a
checkout, produces `out/wmj-skeleton/0.json`, and two consecutive
invocations produce byte-identical file content.

## Scope decisions this chunk makes (not separately pinned upstream)

The specs pin the full pipeline's constants (N=2000 training
trajectories, N=200 eval trials, H=700 steps, etc.) for chunks later in
the build (P3-C07's `prereg/recipe.md`, P6-C01's orchestration loop).
**This chunk is explicitly a smaller-scope skeleton, not the real
pipeline** — the implementation-guide's own MVP-1 framing calls it "the
smallest honest slice of the whole pipeline." Concrete choices made here,
recorded for the reviewer and for P1-C03 (which builds the byte-identity
gate over this exact output):

- Skeleton training set: 8 seeded trajectories, 50 steps each (not the
  real 2000/700 — no `prereg/` numbers exist yet, since `prereg/recipe.md`
  isn't written until P3-C07).
- Skeleton eval set: 20 seeded one-step trials from training-region
  starts, null actions.
- The skeleton scores **persistence** (as "the model") against
  **linear** (as "the baseline") — both created in this chunk — via
  one-step CRPS/skill, matching ADR-J1's `h=1` fixed horizon. This is
  not JU-2's full "vs both baselines" requirement (that needs a learned
  model, not built until Phase 3); it exercises `skill.py`'s real
  arithmetic end-to-end with two genuinely different baselines rather
  than a trivial self-comparison.
- Output schema is `{"schema": "wmj-skeleton/0", ...}` — a distinct,
  minimal report shape, NOT the pinned `wmj-verdict/1` `Verdict` schema
  (judge.md §5), which needs machinery (`JudgeInput`, the full harness
  orchestration loop) this chunk does not build. `wmj/harness/skeleton.py`
  is a throwaway-by-design module distinct from the eventual
  `wmj/harness/trials.py` (ADR-004, P6-C01).
- No `wmj.models.registry` yet (not in this chunk's Wiring Matrix row —
  `models.registry` first appears at a later chunk). The CLI imports
  `wmj.models.baselines` directly and calls its two factories by name.

## Deliverables

1. `src/wmj/worlds/base.py` — `RegionSpec`, `OutRegion`, `Task` (frozen
   dataclasses, worlds spec §4.3).
2. `src/wmj/worlds/integrator.py` — `rk4_step(deriv_fn, state, dt)`, one
   shared, pure, generic fixed-step RK4 (worlds ADR-W1).
3. `src/wmj/worlds/lv.py` — the LV world: `d=2`, `a=1`, `dt=0.02`,
   `scale=(4.0, 2.5)`, `transition(state, action)` (impulse-then-integrate,
   ADR-W2), `conserved(state)` (the V(x,y) invariant), `regions()`,
   `tasks()` — constants exactly per worlds.md §4.1's table.
4. `src/wmj/models/base.py` (extends P1-C01's file) — `Prediction`,
   `WorldContext`, `TrainingData` frozen dataclasses (models ADR-M1).
5. `src/wmj/models/baselines.py` — `persistence_factory` and
   `linear_factory`, both `(ctx, seeds, training) -> Model` (ADR-M1's
   uniform factory signature); mean rules + minimal spread per ADR-M2.
6. `src/wmj/judge/_normal.py` — `Phi`, `phi` (ADR-J1/J2's exact
   formulas, vectorised via `numpy.frompyfunc(math.erf, 1, 1)`).
7. `src/wmj/judge/skill.py` — `crps_gaussian(mean, spread, outcome)`,
   `skill_score(crps_model, crps_baseline)` (ADR-J1 closed form).
8. `src/wmj/harness/skeleton.py` — builds the skeleton report dict and
   writes it via `canonical_serialize`.
9. `src/wmj/harness/cli.py` — `main(argv) -> int`, `run --skeleton`
   subcommand.
10. `src/wmj/__main__.py` — calls `ensure_single_threaded()` before
    importing anything that pulls in NumPy, then delegates to
    `wmj.harness.cli.main`.

## TDD Approach

**TDD-1 applies in full — no exemption.** This is the first user-facing
chunk (Hard Gate 9's MVP-1 slice). The outside-in acceptance test is the
first deliverable: `tests/unit/harness/test_cli.py` invokes
`wmj.harness.cli.main(["run", "--skeleton"])` against an isolated
`tmp_path` cwd and asserts the produced file's contract (required keys,
sane values, two-invocation byte-identity) — written and run Red before
any implementation module exists. Unit tests for the integrator, the LV
world (including TC-WD1-01's hand-verified reference), the baselines,
and `skill.py`'s CRPS/skill formulas fall out from the acceptance test's
failures, built bottom-up, each Red before its own implementation.

## Review Criteria

**Tier 1 (architecture, always-on):** McConnell (defensive programming,
fail loudly on e.g. σ≤0); Hunt & Thomas (DRY, tracer-bullet thin
slices — this chunk *is* the tracer bullet); Keeling (ADR traceability
— code matches the pinned LV constants table and CRPS formula exactly).

**Tier 3 (numerical Python):** Ramalho (dataclasses, type hints);
Hairer/Nørsett/Wanner (RK4 local-error characterisation — grounds
`rk4_step`'s correctness expectations); Goldberg (float determinism —
grounds why the RK4 implementation must do the exact same arithmetic
in the exact same order every time, no shortcuts).

## Framework Reference

`numpy.frompyfunc(math.erf, 1, 1)` for vectorising a scalar stdlib
function over NumPy arrays (no SciPy dependency, NF-3); `argparse`
stdlib for the CLI subcommand; `dataclasses.dataclass(frozen=True)` for
every cross-package value type.
