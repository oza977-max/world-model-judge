# Build Prompt: P3-C07 — Pre-registration tooling

## Chunk Summary

The machinery that makes MU-6 / JU-11 mechanically true: you cannot move a
threshold after seeing results if the thresholds were committed, content-
frozen, and timestamp-ordered before the judged run. Delivers:

1. `wmj/harness/derive_thresholds.py` — computes the exact-binomial bands
   and the per-world threshold constants and writes `prereg/thresholds.json`
   (run once, committed, never re-run after judging — JU-11).
2. `wmj/harness/prereg.py` — `check_prereg(...)` (the git-ordering +
   content-invariance + per-model-entry certification) and `matching_margin`
   reading + the MU-5 margin check.
3. The committed `prereg/` files: `recipe.md`, `prediction.md`,
   `thresholds.json`.

**These are harness modules** (the orchestration edge), so they may do I/O
and shell out to git. The judge never reads git or files (JU-12); the
harness owns the prereg check and passes `thresholds` to the judge as data.

## Deliverables

### `wmj/harness/derive_thresholds.py`
- `binomial_bands(n=200, p=0.10)` → the green/amber/red integer boundaries
  from the **exact** binomial CDF (`math.comb`, no scipy): green = central
  95% acceptance region `[12, 29]`; amber `[8, 11] ∪ [30, 35]`; red beyond.
  Declares the realised outside-probabilities (green 3.31% ≤ 5%, amber
  0.087% ≤ 0.1% — JU-8 per-band false-alarm bounds). These boundaries are
  computed, not hardcoded, and the test asserts they equal the spec's pins.
- `sharpness_hedge_threshold(scale)` → per-dimension width bound. **Pinned
  rule (a pre-registration modelling choice, fixed in advance, flagged in
  the handover): threshold = the world's own `scale` vector** — a mean 90%
  interval wider than the state's characteristic magnitude has said nothing
  (JU-5 anti-hedging; judge ADR-J4). Documented as the chosen rule, since
  judge ADR-J4 pins only "from the world's scale vector," not the formula.
- `agreement_threshold = 1.0` (judge §climatology: standardised deviation
  |z| ≤ 1).
- `write_thresholds(path)` → writes `prereg/thresholds.json` via the project
  canonical serializer (`harness.serialize`, sorted keys, `allow_nan=False`)
  so the file is byte-reproducible. Content: `bands` (green/amber per-world-
  agnostic integer boundaries at N=200), `sharpness_hedge_threshold`
  per world, `agreement_threshold`, and the `(n, p)` the bands derive from
  (so TC-JU11-02's "boundaries inconsistent with declared (N,p)" check has a
  source).

### `wmj/harness/prereg.py`
- `PrereguError(WmjError)` family (e.g. `PreregNotCommittedError`,
  `PreregOrderingError`, `PreregContentError`, `PreregEntryMissingError`) —
  fail loudly and specifically (McConnell).
- `first_added_commit(path, repo)` → the oldest add via
  `git log --reverse --diff-filter=A --format=%H -- <path>`, FIRST line
  (the `--reverse` pin is load-bearing — design-review-008 I6: a
  delete-then-readd produces two `A` events, and default newest-first order
  would resolve to the re-add and silently pass the gaming it exists to
  catch).
- `check_prereg(models, run_timestamp, repo, prereg_dir)` → for every
  `prereg/` file: committed (not dirty); its first-added commit timestamp
  strictly precedes `run_timestamp`; the blob at that commit
  (`git show <sha>:prereg/<file>`) hashes equal to the working-tree file
  (content-invariance — TC-MU6-04). For every **unrigged** model
  (`not is_baseline and not is_fixture`): its `name` appears in the committed
  `recipe.md` and `prediction.md` (TC-MU6-03). `is_baseline`/`is_fixture`
  models are skipped (TC-MU6-05a). Raises the specific error on any failure;
  returns the commit-of-record SHA on success (recorded in verdict metadata
  so TC-JU11-02's after-the-fact edit is detectable).
- `read_matching_margin(recipe_path)` and
  `within_matching_margin(skill_a, skill_b, margin)` → the MU-5 margin read
  + check: the two unrigged models' one-step skill difference is at or under
  the pre-registered margin, else "pre-registration not yet satisfied" and
  judging does not proceed (TC-MU5-01). The value lives in `recipe.md` as a
  machine-readable `matching_margin: 0.05` line.

### `prereg/recipe.md`, `prereg/prediction.md`, `prereg/thresholds.json`
- `recipe.md`: machine-readable key-value lines the training chunks parse
  (`training_trajectories: 2000` [spec-pinned, models §4], `epochs: 100`
  [**pinned here — pre-registered modelling choice, flagged**], `batch_size: 32`,
  `matching_margin: 0.05`), the ADR-M3 constants (2×64 tanh, init, Adam
  lr/β/ε, NLL), the ensemble rules (K=5, `sqrt(1+1/K)·std(ddof=1)`, per-member
  seeding), the seeds policy (content-addressed, ADR-002), the MU-1
  uncertainty format (per-dimension mean + 1 sd), and **named entries for the
  two unrigged models `direct` and `ensemble`** (so TC-MU6-03's per-model
  presence check passes). Plain-English throughout (NF-5).
- `prediction.md`: the written ranking prediction naming `direct` and
  `ensemble` (the MU-5 expected ranking — recorded before judging).
- `thresholds.json`: generated by `derive_thresholds.write_thresholds`.

## Spec Excerpts

- Bands (judge ADR-J4): exact two-sided Bin(200, 0.10); green `[12,29]`,
  amber `[8,11]∪[30,35]`, red beyond; expected 20; 3.3% / 0.087% bounds.
- `check_prereg` (models ADR-M5): committed + first-add-precedes-run +
  content-hash-equals-first-add (`git log --reverse --diff-filter=A`,
  `git show <sha>:path`) + per-unrigged-model name presence; baselines/
  fixtures exempt.
- Training count (models §4): `training_trajectories: 2000`; `epochs:`
  pinned in recipe (value open — see flag below).
- Margin (MU-5): 0.05 one-step skill-score difference.

## Two pinned values the spec left open (flagged for the handover + user)

1. **`epochs: 100`** — models §4 pins `training_trajectories: 2000` but
   leaves `epochs: <pinned>`. 100 is a round pre-registered figure. Its
   convergence-and-runtime feasibility (NF-2 600 s budget) is validated at
   P3-C03/C06 against real training; the training-trajectory horizon is also
   unpinned and couples to this. Recorded as **backlog A12**: the
   "P3-C07 precedes C03/C06" ordering pins these counts before their runtime
   is measurable — an honest ordering tension, resolvable by an open recipe
   revision before any judged run if needed.
2. **`sharpness_hedge_threshold = scale`** — judge ADR-J4 pins only "from
   the world's scale vector," not the formula. Chosen rule documented above;
   also in backlog A12 for design-review ratification.

## TDD Approach

**TDD-1 exempted: harness/library tooling, no user-facing surface — consumed
by `wmj run`/`wmj verify` at P6. The git-ordering and content-invariance
tests (each building a throwaway git repo in `tmp_path`) are the chunk's
first deliverables.**

Order:
1. `binomial_bands` → assert `[12,29]` / `[8,11]∪[30,35]` and the declared
   outside-probabilities (Red-first).
2. `write_thresholds` round-trips; byte-reproducible; bands match.
3. `check_prereg` happy path: a `tmp_path` git repo with committed prereg
   files dated before the run → passes, returns the commit SHA (TC-JU11-01,
   TC-MU6-01).
4. **Phantom-gate TC-MU6-04:** first-add placeholder, honestly-dated second
   commit changing content → `PreregContentError`.
5. **Phantom-gate TC-JU11-02:** thresholds file first-committed AFTER the
   run timestamp → refuses.
6. TC-MU6-03: an unrigged model whose name is absent from recipe →
   `PreregEntryMissingError`; present → passes.
7. TC-MU6-05(a): an `is_baseline` model is skipped by `check_prereg`.
8. TC-MU5-01: margin read from recipe; difference ≤ margin passes, > margin
   is "not yet satisfied" (judging does not proceed).
