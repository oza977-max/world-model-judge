# Build Prompt: P3-C02 — Baseline spreads + model registry

## Chunk Summary

Deliver the **model registry** — the single name→factory table that is
MU-9's whole extensibility story (a model exists to the harness only if it
registered) — and **wire both baselines into it**. The baselines'
behaviour, spreads, `reset()` isolation, and `is_baseline`/`is_fixture`
flags were already built across P1-C02 / P2-C05 / the Round-9 A8 fix;
this chunk's genuine new surface is `wmj/models/registry.py` plus the two
module-level `register(...)` calls in `baselines.py`.

**Scope carve (important):** per the implementation guide's wiring matrix,
`wmj.models.registry` is "consumed by `harness.trials` discovery … wired
at P6-C01," and **TC-MU9-01** (the auto-discovery + isolation acceptance
test) is a **P6-C01** test. So this chunk builds the **registration
substrate only** — `register()`, `all_models()` in the pinned sorted-name
order, `DuplicateModelError`. The **auto-discovery half** of `all_models()`
(the `importlib.invalidate_caches()` + `pkgutil.iter_modules(wmj.models.__path__)`
scan that imports every model file so its module-level `register()` fires,
cross-cutting ADR-003) is built at **P6-C01**, where it is first consumed
and where TC-MU9-01 tests it. Nothing enumerates the roster before P6-C01,
so deferring discovery changes no behaviour reachable today.

**Backlog A11 (recorded this chunk, decided at P6-C01):** cross-cutting
ADR-003 specifies the registry's discovery via `importlib`/`pkgutil`, but
the *same* ADR-003's models import-allowlist says the models package may
import "numpy, math, dataclasses, typing, `__future__`, `wmj.errors`,
`hashlib`, `wmj.models.base`, `wmj.models.registry` — nothing else, in any
direction" (enforced by the TC-NF6 gate at `MODELS_ALLOWLIST`). Those two
clauses contradict: `importlib`/`pkgutil` are required by the discovery
clause and forbidden by the allowlist clause. It was never caught in nine
design-review rounds because the registry had not been built. Deferring
discovery to P6-C01 keeps this chunk's `registry.py` inside the allowlist
(`typing` + `wmj.errors` only) and defers the security-gate carve-out to
where discovery is actually consumed and testable.

## Spec Excerpt (models ADR-M1, the registry contract)

```
wmj.models.registry:
  register(name, factory) -> None
      # module-level call at import time; raises DuplicateModelError if the
      # name is already registered
  all_models() -> dict[str, Factory]
      # returns the registered factories keyed by name, in SORTED-NAME order
      # (ordering is part of the contract; model_ref indices assigned in it)
```

Cross-cutting ADR-003: `wmj/models/*` may import only numpy / math /
dataclasses / typing / `__future__` / `wmj.errors` / `hashlib` /
`wmj.models.*` (TC-NF6-07/08/09). `registry.py` therefore imports only
`typing` + `wmj.errors`; `baselines.py` may import `wmj.models.registry`.

## TDD Approach

**TDD-1 exempted: internal helper (the model registry), no user-facing
surface — it is consumed by `harness.trials` at P6-C01, not by any CLI/UI
route. The registration-substrate tests are the chunk's first deliverable.**

Order:
1. **FIRST test (Red):** `test_register_then_all_models_returns_the_factory`.
2. Implement `register` / `all_models` / `DuplicateModelError` until Green.
3. `test_all_models_is_in_sorted_name_order` (register out of order, assert keys sorted).
4. `test_register_refuses_a_duplicate_name` (phantom-gate — the fail-loud guard fires).
5. `test_all_models_returns_a_fresh_dict` (mutating the result does not corrupt the registry).
6. `test_both_baselines_are_registered_under_their_names` (importing `baselines` registered `persistence`/`linear` and they are the real factories).

Tests that register throwaway names must snapshot/restore `_REGISTRY`
(baselines auto-register into the same global on import) so they leave the
real roster intact — mirror TC-MU9-01's snapshot/restore discipline.
