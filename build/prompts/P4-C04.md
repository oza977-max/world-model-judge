# Build Prompt: P4-C04 — Exception counting and the pre-registered bands

**In plain words:** the banking-style backtest. Each of the 200 independent test starts is a
bet the model made: "the truth will land inside my 90% range". Count the misses — an
"exception" — and compare the count with what a perfectly honest 90% model would produce:
about 20 of 200. The count falls in a colour band fixed in advance: green (12–29, what honest
luck looks like), amber (8–11 or 30–35), red (anything further out). Too many misses means
over-confidence; too *few* means the ranges are padded — so a low count on a model whose
ranges are very wide is flagged, never rewarded. The same per-trial hit/miss list that the
count is made from is what the main chart draws, so the chart and the count cannot disagree.

## Chunk Summary
From `specs/implementation-guide.md` v2.0 P4-C04 and judge spec ADR-J4 (exception = outcome

TC-JU9-03 (observed == sum of flags, property test).

## Conventions pinned here (also backlog A32)
- **Exception test:** trial `i` at step `h` is an exception iff *some* quantity has `|outcome − mean| > z90 · σ` (z90 = 1.6449; the edge itself is inside, as for coverage).
- **Entries:** for each task and region, one entry at h = 1 and one at h = h_task (just one when h_task = 1), `n_trials` = the region's trial count (which must equal the pre-registered `bands.n`), `expected` = `n · p`, `observed` = the count, `band` by the pre-registered bands, `bands` copied from the input's thresholds as `{green: [lo, hi], amber: [[a_lo, g_lo − 1], [g_hi + 1, a_hi]], red: "outside"}`.
- **`trials` block (for the main chart):** per entry, `outcome_distance[i]` = RMS over quantities of `outcome − mean` (the arrays are already normalised); `band_hi[i]` = RMS over quantities of `z90 · σ` — the interval's *radius* in the same distance unit, because the distance is measured from the mean (the spec says "width"; a full width would draw misses as hits — A32); `band_lo` = 0; `is_exception[i]` = the per-quantity joint test above, **never** re-derived from the two distances. `observed` is `sum(is_exception)` by construction.
- **Hedging flag:** `low_side_sharpness_flag` is true when the count is green-or-better (`observed ≤ green_hi`) **and** the region/task's mean 90% width (`compute_sharpness`) exceeds the mean of `thresholds.sharpness_hedge_threshold`. The threshold must be in the arrays' units: the harness divides it by the scale like everything else (A30), which makes the ratified "= scale" rule the number 1.
- **Bands that cannot be written out:** if the pre-registered bands have no amber range on one side (tiny n), the judge refuses (JudgeInputError) rather than invent one; unreachable at N = 200.
