# Build Prompt: P3-C09 — Batched world step + kick generator + action-axis region + kicked benchmark

**In plain words:** this chunk gives the two worlds three things Round 10
decided they need before any training data can be made. (1) A way to step
many states at once (`transition_batch`) that gives exactly the same numbers
as stepping them one by one — so 2,000 training runs and 200 test runs per
region take seconds, not minutes. (2) The one "kick generator" that decides
when the lever is pulled and how hard — the same generator for training,
testing and the drift benchmark. (3) A third region in each world,
`out-large-action`, where the starting states are familiar but the kicks are
bigger than anything seen in training — the only way to test WD-5's "unfamiliar
command" axis. And it re-runs the drift benchmark with the same kicks applied
to both twin runs, so the "how fast the world drifts on its own" line is
measured under the same conditions the models are graded in.

## Spec Excerpt
**worlds ADR-W1 (batched step):** one batch-aware derivative per world (indexes `S[..., i]`, `np.sin`/`np.cos`), used by `transition(state, action)` (1-D only; else `WorldInputShapeError`) and `transition_batch(states[n,d], actions[n,a])`; both call the same `rk4_step`. Row `i` bit-identical to `transition(states[i], actions[i])` — TC-WD3-04, `np.array_equal`, n ∈ {1, 2, 7, 64, 200}, both worlds, kicked actions included. `transition_batch` applies the same action-range and floor checks row by row; any failing row aborts the call (§7).

**worlds ADR-W2 (kicks):** `kick_sequence(rng, horizon, p_step, band, umax) -> float64[horizon, 1]`; `r = rng.random((horizon, 3))`; kick at t iff `r[t,0] < p_step`; `"in"`: `u = umax·(2·r[t,1] − 1)`; `"out"`: `u = s·umax·(2 − r[t,1])`, `s = +1` if `r[t,2] < 0.5` else `−1`; else `0.0`. `p_step = kick_rate_per_s × dt` (LV 0.5 × 0.02; pendulum 1.0 × 0.002). `umax` = the world's trained half-width. Purposes: `"train-kicks"`, `"eval-kicks"`, `"benchmark-kicks"`, indexed per trajectory/trial/start.

**worlds ADR-W3:** benchmark start `i` of region `r` draws one kick sequence from `seeds.rng_for(world, r, "benchmark-kicks", str(i))` with the region's band, applied identically to trajectory and twin. Drift check (TC-WD3-03) stays null-action. Executed: LV ratio 0.92 (gate 0.1–10), pendulum inverted/training ≈3,500× (gate ≥5×).

**worlds ADR-W4 / §4:** `"out-large-action"`, `axis="action"`, state box = training box, kicks from the out band. LV trained `[−0.1, 0.1]`, out `(0.1, 0.2]`, 0.5/s; pendulum `[−1, 1]`, `(1, 2]`, 1/s. §7: region validation — for the action-axis region the disjoint axis is the action band. Kick safety tested at full scale (TC-WD2-02).

**Cross-cutting ADR-002 rule 2:** the three kick purposes are distinct from `"train-starts"`/`"eval-starts"`/`"benchmark-starts"` and from each other (TC-NF1-10).

## Framework Reference
- NumPy 1.26: `np.random.Generator.random(size)` → floats in `[0, 1)`; ellipsis indexing `S[..., 0]`; `np.stack(arrays, axis=-1)`; `np.sin/np.cos` ufuncs (element-wise, broadcast); `np.array_equal` for exact equality; `ndarray.ndim`, `.shape`.
- Python 3.11 `math.sin` — measured bit-identical to `np.sin` on 2,000,000 values in this environment (NumPy 1.26.4) — the test, not the measurement, is the guarantee.
- pytest: `pytest.mark.parametrize`, `pytest.raises`, the project's `slow` marker (`pyproject.toml`).
