# Build Prompt: P3-C10 — The one-time freeze

**In plain words:** before the judge may grade the two practice models, the
recipe, the written prediction and the pass/fail thresholds must be locked.
Until now the lock was "each file's first commit" — which made the spec's own
remedy ("revise the recipe openly, before any result") fail forever, and the
first replacement idea (a chosen commit plus a git tag) could be moved
silently. This chunk builds the lock Round 10 settled: the freeze is the one
commit that added `prereg/FREEZE`, read from git history, never typed in.
It can happen once, ever. After it, nothing locked may change, the freeze must
come before the run, and the recipe's kick settings must match the worlds'
own. The checker hands back the freeze commit so every verdict can say which
locked version it was judged against.

## Spec Excerpt (models ADR-M5, v2.0 — "The freeze")
- `prereg/FREEZE` is a short human-readable declaration (date, a sentence); it contains no commit id.
- The freeze commit is the commit that added `prereg/FREEZE`, read from git history, never chosen or typed. `check_prereg` refuses unless `git log --diff-filter=A --format=%H -- prereg/FREEZE` prints exactly one line and `git log --diff-filter=D --format=%H -- prereg/FREEZE` prints none — one freeze, ever (TC-MU6-06). No `FREEZE` → refused as "not frozen yet" (TC-MU6-08).
- Every certified file — `recipe.md`, `prediction.md`, `thresholds.json` and `FREEZE` itself — must be clean in the working tree and byte-equal to its blob at the freeze commit (TC-MU6-04); the freeze commit's timestamp must strictly precede the run (TC-MU6-01).
- `check_prereg` returns the freeze commit SHA (→ `meta.prereg_commit`, P6-C01 — TC-MU6-07).
- The git tag `prereg-freeze` is an optional human label; `check_prereg` never reads it.
- Before the freeze, `recipe.md`/`prediction.md` may be revised openly.
- The recipe's kick and action-interval keys must equal the world modules' constants (TC-MU6-09).
- Residuals disclosed: rewritable git history; non-publication; forgeable timestamps; entry substance (A13); no evaluation-trial metric before the freeze (procedural).
- Executed before pinning: one freeze → 1 add, 0 deletes; delete + re-add → 2, 1; rename away and back → 3, 2; an in-place edit of FREEZE is caught by the content check.

## Framework Reference
- `git log --diff-filter=A|D --format=%H -- <path>` (no `--follow`: a rename shows as D + A at the path); `git show <sha>:<path>`; `git status --porcelain -- <path>`; `git show -s --format=%ct <sha>`; `GIT_AUTHOR_DATE`/`GIT_COMMITTER_DATE` = `@<unix> +0000` in tests.
- `re.MULTILINE` anchors for `key: value` lines; `hashlib.sha256`.
