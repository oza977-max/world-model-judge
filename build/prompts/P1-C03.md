# P1-C03 — Gates

## Scope

Per `specs/implementation-guide.md` line 35: `tests/gates/` — the judge
import-allowlist AST lint and its family (banned-identifier scan,
wholesale `numpy.random` ban, the evasion-fixture regression corpus,
the clean-pass guard, the models→worlds/harness/judge/reporting import
gates), the WD-3 dt-alignment gate + its negative, and the ten-run
byte-identity harness over P1-C02's skeleton output.

**Spec:** `specs/cross-cutting.md` ADR-003 (the full TC-NF6 family,
verbatim mechanisms); `specs/worlds.md` ADR-W1 (WD-3, dt-alignment).

**Tests:** TC-NF6-01, -02, -03, -04, -06, -07, -08, -09; TC-WD3-01
(**skeleton scope** — LV eval-truth integrator only; the full
three-generator identity check needs `wmj.harness.benchmarks` and a
separate training-data-generation module, neither of which exists
until P2-C03/P3-C06, per design-review-006), TC-WD3-02 (dt-alignment
negative); TC-NF1-01 (**skeleton scope** — the ten-run separate-process
byte-identity gate runs over P1-C02's `out/wmj-skeleton/0.json`, not
the full pipeline's verdict, since no `Verdict`/`JudgeInput` exists yet).

## Scope decisions this chunk makes

- **TC-WD3-01's skeleton-scope reading.** At this build stage there is
  exactly one ground-truth call site: `wmj.worlds.lv.transition`,
  called from both of `wmj/harness/skeleton.py`'s functions
  (`_generate_training_data`'s step loop and `_run_one_step_trials`'s
  outcome computation). The gate checks this structurally: both call
  sites are AST-confirmed to call `lv.transition` (not a private
  reimplementation), and `lv.transition` is confirmed, by runtime
  identity (`is`), to route through the one shared
  `wmj.worlds.integrator.rk4_step` function object with the module
  constant `lv.DT` — not a re-derived or hardcoded local value. This is
  the honest, buildable form of "every ground-truth generator shares
  one integrator and dt" until more generators exist (full check at
  P6-C01, per the implementation guide's own note).
- **TC-WD3-02's negative, built as a reusable checking function.**
  `worlds.md` ADR-W1's own wording frames this as "the harness's
  model-rollout loop advances a model exactly once per ground-truth
  step." Rather than only asserting today's hardcoded 1:1 alignment,
  this chunk extracts the check into a small reusable function,
  `tests/gates/_dt_alignment.py::assert_dt_alignment(world_dt,
  model_dt)`, so the negative case (mismatched dt) can be demonstrated
  against the function directly — proving the check can genuinely
  fail, not just narrating that it "would."
- **TC-NF1-01's skeleton-scope reading.** The gate runs `python -m wmj
  run --skeleton` ten times, each in its own subprocess, and compares
  `out/wmj-skeleton/0.json` byte-for-byte across all ten — the full
  pipeline's `Verdict`-based byte-identity gate (over `out/verdicts/`)
  is a later chunk's concern once that machinery exists.
- **Fixture corpus scope.** `tests/gates/fixtures/` contains one
  minimal `.py` file per evasion TC-NF6-04 names by category (not one
  per historical review round) — the corpus is the *regression floor*
  for the lint, not a completeness proof (cross-cutting ADR-003).

## Post-review addendum (independent review pass 1 findings, fixed)

Four findings changed this chunk from what was first written:

- **The string-concatenated-identifier fixture didn't test what it
  claimed.** It was flagged only because it also called `getattr` on
  `__builtins__` — both already-banned identifiers — with the
  concatenation itself playing no role. Fixed: the fixture's own
  docstring now says so plainly, explaining that Python gives no way
  to invoke a computed name without going through one of the banned
  identifiers, so the fixture is *necessarily* confounded with the
  getattr/reflection category, not independently proving concatenation
  detection.
- **TC-WD3-01's "both call sites" test could only prove one call
  site existed**, not that both of the two named functions call it —
  a module-wide set check collapses to a single boolean. Fixed:
  rewritten to check each named function (`_generate_training_data`,
  `_run_one_step_trials`) individually.
- **TC-WD3-01's dt-alignment check was circular** — `lv.WORLD.dt ==
  lv.DT` is guaranteed true by both names pointing at the same module
  constant, and said nothing about what `transition()` actually passes
  to `rk4_step`. Fixed: added an AST check on `transition()`'s own
  source confirming the third argument to `rk4_step` is the `DT` name,
  not a coincidentally-equal literal.
- **The models-side import gate was a 4-item denylist, not the full
  allowlist cross-cutting.md's own ADR-003 text claims is enforced**
  ("only sanctioned outward imports... nothing else, in any
  direction") — `import os` or `import requests` inside a models file
  would have sailed through uncaught. Building the real allowlist
  surfaced that the spec's own list is incomplete: real, already-
  reviewed code (`wmj/models/base.py`) needs `wmj.errors` (the shared
  exception base) and `hashlib` (`component_key`'s blake2b digest,
  ADR-002 rule 2), neither named in cross-cutting.md's "complete" list.
  Fixed: built a genuine full allowlist (matching TC-NF6-01's rigor for
  the judge package), added both omitted names with rationale recorded
  in `test_import_graph.py`'s own module docstring, and flagged the
  spec text as a future design-review correction candidate rather than
  silently editing the already-reviewed document.

## Deliverables

   by every TC-NF6 check: `top_level_import_names`, `joined_importfrom_names`
   (the module+name join TC-NF6-07/08/09 need), `scan_banned_identifiers`,
   `scan_numpy_random_usage`.

   `compile` payloads, both `numpy.random` import idioms, identifier

   model_dt)`, `DtMismatchError`.

   TC-WD3-02 (negative, via `_dt_alignment.py`).
6. `tests/gates/test_byte_identity.py` — TC-NF1-01 (skeleton scope,
   ten separate-process subprocess runs).

## TDD Approach

`TDD-1 exempted: this chunk's deliverables ARE tests — there is no
separate outside-in acceptance surface to write first; each gate test
is written directly against a fixture or the real source it checks,
confirmed to fail (flag/raise) on the bad case and pass on the good
case before being considered done.` Order: `_ast_utils.py`'s own unit
tests first (tiny synthetic ASTs) → the fixture corpus → the import-graph
gate tests (run against fixtures, then against real judge/models
source) → `_dt_alignment.py` + its gate test → the byte-identity gate.

## Review Criteria

**Tier 1:** McConnell (fail loudly, precise error messages); Fagan
(a gate with no can-fail case is not a gate — every TC-NF6/-WD3 check
here has a paired positive+negative or corpus proof).

**Tier 3:** Ramalho (AST/`ast` module idioms); Bratus/Patterson/Sassaman
(LANGSEC — the allowlist-not-denylist framing this whole gate family
is built on: recognise fully, don't enumerate exceptions).

## Framework Reference

stdlib `ast` module (`ast.walk`, `ast.parse`, `ast.Import`,
`ast.ImportFrom`, `ast.Name`, `ast.Attribute`); `subprocess.run` for
the separate-process byte-identity harness; `pathlib.Path.rglob` for
locating fixture files and real source files to scan.
