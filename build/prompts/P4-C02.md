# Build Prompt: P4-C02 — Skill scores per task and region

**In plain words:** the judge never reports "the error was 0.03". It reports *skill*: how
much better the model's whole forecast (its guess and its stated uncertainty, scored together
by a rule that cannot be gamed) is than the two simple reference forecasts — "nothing changes"
and "straight line". Zero means no better than the reference, one means essentially perfect,
negative means worse. This chunk computes that for each task and each region, one step
ahead, and hands it to the verdict in exactly the shape the spec fixes: `vs_persistence`,
`vs_linear` and the model's own score — and nothing else, however many other simple models
exist elsewhere in the project (the judge cannot see them).

## Chunk Summary

skill = 1 − CRPS_model / CRPS_baseline, one-step horizon h = 1, per task and region) and §5

## Conventions pinned here (also backlog A30)
- **Normalised units.** The judge computes in the units its arrays arrive in; the harness divides by the world's scale vector before handing them over (ADR-J1: "we use normalised units"; `skill.py` already says so). `JudgeInput` carries no scale vector, so the judge cannot normalise itself — the spec's `JudgeInput (complete)` list has none.
- **Step indexing.** Forecast and outcome arrays `[n, H, d]` hold steps 1..H (array index `k` is step `k + 1`); divergence curves `[H + 1]` are indexed by step from 0. One step ahead (h = 1) is array index 0.
- **Per (task, region).** Every task in every region present gets an entry; because skill is pinned to h = 1 the values are the same for every task of a region (the keying rule still requires the explicit `task` and `region` fields). Order: tasks as given, regions sorted by name.
- **CRPS aggregation.** Closed-form Gaussian CRPS per trial and quantity, averaged over quantities, then over the region's trials. The reported `crps` is the model's.
