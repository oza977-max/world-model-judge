# P2-C01 — LV full

## Scope

Per `specs/implementation-guide.md` line 39: "Regions, tasks, conserved
V, clamp guard, action-range validation." Runs parallel with P2-C02.

**Spec:** `specs/worlds.md` §4.1 (LV constants and tasks table), §7
(error handling — clamp/action-range abort rules), ADR-W3 (the shared
normalised-distance metric), ADR-W4 (region membership).

**Tests:** TC-WD1-01, TC-WD2-01 (already built and passing from
P1-C02 — re-confirmed here, no new work needed), TC-WD6-01 (task
distinctness: control vs planning, quantitatively different
tolerances), TC-WD6-02 (boundary determinism: exact-tolerance values
classify deterministically, closed/≤).

## Scope decisions this chunk makes

- **Regions/tasks/conserved/clamp-guard/action-range-validation are
  already built** (P1-C02's `wmj/worlds/lv.py`, hardened during
  P1-C03's independent-review rounds into loud aborts rather than
  silent clamps). This chunk's real new work is narrower than its name
  suggests: **TC-WD6-01/02**, which P1-C02 declared tasks for but never
  wrote dedicated tests against, and TC-WD6-02's underlying mechanism
  (a tolerance boundary comparison), which doesn't exist in the
  codebase at all yet.
- **TC-WD6-02's comparison function's home.** worlds.md §4.1 states the
  convention ("band-edge classification uses ≤ (closed)") but never
  says which module owns the actual comparison code — the shared
  normalised-distance metric (ADR-W3) is declared once in worlds.md but
  implemented twice by design (judge can't import worlds, ADR-003 — the
  same deliberate-duplication pattern already used for
  `WorldContext`/`Task`/`RegionSpec`). This chunk adds the **worlds-side**
  copy — `distance(a, b, scale)` and `within_tolerance(distance_value,
  tolerance)` in `wmj/worlds/base.py`, pure functions using the world's
  own declared `scale` vector (ADR-W3) — since `worlds` is where `scale`
  already lives and WD-4's divergence benchmark (P2-C03, next) needs
  the same formula. The **judge-side** copy (`wmj/judge/distance.py`,
  ADR-J5) is a later chunk (Phase 4), per the judge package's own
  component-design list.

## Deliverables

1. `src/wmj/worlds/base.py` (extends P1-C02's file) — `distance(a, b,
   scale) -> float` (RMS over normalised dimensions, ADR-W3's formula)
   and `within_tolerance(distance_value, tolerance) -> bool` (closed,
   `<=`).
2. Tests for TC-WD6-01 (LV's two tasks have quantitatively different
   tolerances) and TC-WD6-02 (a distance exactly equal to tolerance
   classifies as within-tolerance, deterministically, not an
   off-by-one).

## TDD Approach

TDD-1 not applicable (no user-facing surface this chunk touches).

## Review Criteria

Tier 1: McConnell (boundary conditions handled explicitly, not by
accident); Keeling (ADR traceability — this is ADR-W3's formula,
cited exactly). Tier 3: Ramalho (pure functions, type hints); Goldberg
(float equality at an exact boundary — `<=` on IEEE-754 doubles is
well-defined and deterministic, which is exactly why the spec pins
`<=` rather than leaving boundary behaviour to an epsilon comparison).
