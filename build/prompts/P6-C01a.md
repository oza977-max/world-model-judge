# Build Prompt: P6-C01a — The orchestration loop (`harness/trials.py`)

> **Note added during the build (2026-10-27).** This prompt was written before the owner's warm-start decision. The rollout is now `roll_out(model, warmups, starts, kicks, name)`, and pinned decisions 1 and 9 are superseded by backlog A43 item 6. Read A43 for the loop as built; this text is the record of what was planned.

**In plain words:** this chunk builds the loop that runs the whole test. For each world it does seven things, in a fixed order:
1. it makes the world's training data;
2. it draws the same 200 test starting points per region for every model;
3. it runs the true world forward from them, with each trial's own seeded kicks;
4. it runs the two simple baselines first;
5. it runs every other model from the same starts with the same kicks, each model feeding its own guesses back into itself;
6. it hands everything, in the judge's units, to the judge, once per model and world;
7. it wraps each verdict with the model's name, its fixture label, the run facts and its action-lever check.

It writes nothing. The writer (P5-C04) does that, and the `wmj run` command (P6-C01b) joins the two.

The pre-registration rule shapes the tests: the two real models (`direct`, `ensemble`) must not be evaluated before the freeze. The fixtures are built on `direct`'s trained core, so they must not be either. The tests therefore run this loop on a stand-in roster: the two real baselines, the real fixture classes wrapped round a stand-in core, and small test-only models. They run at small sizes. The loop is the same code `wmj run` will call.

## Pinned decisions
1. **Free-running rollouts.** At step 1 the model gets the true start. After that it gets its own previous guess (`mean`), plus the trial's true kick for that step. The spread recorded at step h is the error bar the model states for step h, from the state it was given.

   The spec never says this in so many words. But it is the only reading the interface allows: `predict` gives one step. It also matches three other places:
   - the requirements: "feeds its own guesses back into itself … small errors pile up";
   - the chart-preview producer: persistence holds the start constant;
   - the linear baseline's rule: current + (current − previous).

   Record it in the backlog (A43) for the next design review.
2. **Truth.** Truth is computed once per (world, region), from the starts and kicks, using `world.transition_batch`. Every model shares it. The harness never imports the integrator (WD-3).
3. **Units (A30).**
   - Divide predictions, spreads, outcomes and both baselines by `world.scale`.
   - Hedge threshold = raw threshold / scale.
   - Tolerances are passed as declared, because they are already normalised distances.
   - Divergence curves come from `build_divergence_artefact(...)["regions"][r]["median_separation"]` (normalised).
   - Climatology: one table per region (`build_climatology_table(region_name=r)`), scaled through `judge_tables(table, (r,), scale)`.
   - Invariant bins: `measure_invariant_bins(world, raw truth rows of r, table_r)`.
4. **Task horizon.** It is `min(task.horizon, H)`. In production H is the world's longest task horizon, so this changes nothing; it exists so that small tests can run short rollouts.
5. **Bands.** `bands.n` must equal `config.n_trials`. Otherwise refuse: the judge would refuse too, but later and less clearly.
6. **Baselines.** The roster must hold `persistence` and `linear`, or the run refuses (MU-2). They run first (the ADR-004 pre-pass). `baseline_names` = every roster model whose instance has `is_baseline` (for the writer's action sentence).
7. **`model_ref`** is the model's index in the sorted roster names, the same in both worlds.
8. **The envelope** has six keys. `action_response` is `asdict(check_action_response(model, ctx, run_seed, n_states=config.probe_states))`. `meta` is passed in by the caller and copied into every envelope unchanged.
9. **Seeds.**
   - Harness draws use `SeedSource(run_seed, None)`.
   - Each factory gets `SeedSource(run_seed, name)`.
   - Starts come from `rng_for(world, r, "eval-starts")`.
   - Kicks come from `seeded_kick_sequences(..., "eval-kicks", N, H)`, with band `band_for_axis(axis of r)`.
10. **Stateless models** step all N trials together through `predict_batch`. **Stateful models** (`linear`) run trial by trial after `reset()`. A model's output must be finite and the right shape, or the run refuses.

## TDD Approach
1. **Outside-in (red first):** `run_trials` runs on a stand-in roster at small sizes. Its envelopes pass `writer.check_run` and are written by `writer.write_run` into `tmp_path`. Both worlds and every model are present, and the fixture label is carried.
2. TC-NF1-09: the shapes and regions of a `JudgeInput`. Capture it by wrapping `judge_one`.
3. TC-NF1-05: starts are byte-identical across models. Mutation: key the draw on the model name, and the test fails.
4. Free-running: a model that records its inputs gets the true start at step 1 and its own previous means afterwards. The batched and per-trial paths give identical arrays.
5. MU-7: an evaluation start planted equal to a training start is refused.
6. TC-MU6-05(b): an extra `is_baseline` stand-in leaves exactly the `vs_persistence` / `vs_linear` skill keys.
7. Refusals: a missing baseline; `bands.n` ≠ N; a bad model output.
8. Determinism: two in-process runs give identical envelopes.
9. TC-WD3-01 full; TC-MU9-01(b).

## Review Criteria
- Never evaluates `direct`, `ensemble` or a fixture on `direct`'s core in any test (the A42 pre-freeze rule).
- The judge is called once per (model, world). Starts and truth are shared across models.
- Everything is in judge units. Climatology bins are measured from raw true states at every step.
- No integrator import. A model is advanced once per truth step.
- Deterministic order. No hidden state between models (a fresh factory call per model and world).
- Fail loudly. Nothing is returned partly built.
- An "In plain words" docstring. The import gate runs in the same command as the commit.
