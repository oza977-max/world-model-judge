# Build Prompt: P4-C06 — Blindness and purity properties of the judge

**In plain words:** three promises about the judge, each proved by a test that can fail.
(1) *Blind:* it cannot tell which model it is judging — relabelling the regions, or reordering the
trials, changes nothing but the labels and the order. (2) *Pure:* it is a calculation, not an
activity — while it runs, every known route to the clock, the files, the environment variables, the
network, other programs and random numbers is rigged to raise an error, and the judge finishes
without tripping any of them; and the rigging is shown to work by planting an impure read in a copy
of the judge and watching it get caught, including when the read is hidden behind a reflection
trick. (3) *Not learned:* nothing in the judge is trained — no weights, no inference — checked by
reading its code and its imports.

## Conventions pinned here
- The guard is test infrastructure (`tests/gates/_purity_guard.py`), not part of the judge or harness: it rigs `os` (effectful functions, process creation, and the *class* of `os.environ`), `builtins.open`/`io.open`, `time`, `socket`, `subprocess`, every public callable of `numpy.random` at the top level and in each private submodule that binds it, and replaces `numpy.datetime64`, `datetime.datetime` and `datetime.date` (C types: a disclosed rebind). Everything is restored in a `finally`.
- Phantom-gate cases run a *scratch copy* of the judge package in a temporary directory (package name rewritten), mutated to make the impure call; the unmutated scratch copy must pass (can-fail proof).
- Label-swap invariance has no model label to swap (there is none by type — TC-JU1-01); the property is relabelling regions consistently and permuting trials consistently, and judging identical content twice.
- TC-JU12-04 checks the *specs* state the residual (`ctypes`, pre-captured references; byte-identity as backstop). The third place, reporting's methods note, does not exist yet (P5) and is recorded in REMEMBER.
