The Structural Recommendation

Critical Path Recommendation: Change Fixing Strategy Before Round 5

Four rounds, four "Do not build" verdicts, and a Build Check created specifically to prevent a recurring pattern (BC-1) has now recurred through the very round meant to close it. This is not evidence the review process is failing — every citation in this report was independently reached by 2+ reviewers with zero shared context, and one panel this round used ground-truth verification to correctly overturn a wrong finding. The process is working. What isn't working is fixing findings one at a time and re-reviewing the whole document set from scratch each round.

The recommendation, concretely: before a Round 5, do a single deliberate, non-review pass that:

  1. Canonicalize the Verdict schema: Give every block one canonical (task, region, horizon_step) keying convention, applied uniformly, checked once by writing out the full schema and verifying every block against every ADR that defines a fact varying by one of those three axes — not chart-by-chart as each is separately noticed.
  2. Resolve the layering question: Clarify the wmj.models ↔ wmj.worlds layering explicitly, as an architecture decision with its own ADR, rather than letting each fixture's design silently assume an answer.
  3. Fix AST-check evasions: Replace every remaining "enumerate the call shapes I can think of" AST check with the "ban the enabling name/import outright" pattern the project's own TC-NF6-03 already demonstrates works.
  4. Reconcile the implementation guide: Do one pass reconciling implementation-guide.md against the full current requirements/test-case/spec set, chunk by chunk, rather than patching only the specific line each round's findings happened to touch.
  5. Remove undisclosed dependencies: Remove or properly scope the two new "mitigations" that quietly introduced network/CI dependencies (the GitHub push-timestamp check, the disclosed-but-unbuilt CI backstop) contradicting the project's own "no external systems but git" architecture claim.

Rationale: Capture-recapture logic (used after Round 1) implies this now: four rounds of finding a comparable population size each time means the population isn't shrinking through incremental fixes — the fix strategy itself needs to change, not just continue at higher review depth. This is the textbook case per this project's own Build Check BC-2 logic extended to its natural conclusion: if adversarial pressure-testing keeps finding the fixes wrong, the fixing process itself — not just each individual fix — needs to change.

What Held From Round 3, and Failed This Round

The two highest-priority items flagged for pressure-testing — fx-brittle's redesign and the registry auto-discovery/TC-MU9-01 mechanism — were pressure-tested hard this round, and both failed, in ways more serious than what they replaced:

  • fx-brittle's new corruption rule requires importing a worlds-package constant into the models package — directly contradicting models.md's own stated rule, in the same document, that "models never import world internals." Six independent panel-runs (across four different panels) converged on this, unprompted.
  • The new TC-MU9-01 structural test and the fx-brittle fix are mutually exclusive: the only layering-preserving way to fix fx-brittle's import problem requires harness.trials to reference fx-brittle by name — which is exactly what the new TC-MU9-01 AST-walk is built to fail on.
  • The new mechanism's own cleanup step has no exception-safety, and because it writes into the actual production model directory (not a scratch location), a failed test run can leave a phantom model that a real wmj run then executes.
  • The two brand-new AST checks added this round both use the exact "enumerate call shapes" technique that a third check three lines earlier explicitly identifies as insufficient and replaces. Four independent panels found concrete one-line evasions.
  • implementation-guide.md has only ever been touched for chunk-count arithmetic and was never reconciled against the growing spec/test suite: its Wiring Matrix still describes a disproven mechanism, 10 of 79 test cases are never wired to any build chunk (including the sole test for a Must requirement, unwired since Round 1), and its critical path is still wrong.
  • BC-1 (the schema/consumer granularity Build Check, promoted specifically to stop this) recurred a fourth consecutive round — in the very blocks Round 3 restructured.

New Findings — Critical

NC-1 — fx-brittle's corruption rule violates the models layering constraint

6 independent panel-runs

fx-brittle's corruption rule requires importing a wmj.worlds region-box constant into wmj.models.fixtures, directly contradicting models.md's own stated rule ("models never import world internals — they see (state, action) arrays") and architecture-overview's container view ("Sees (state, action) arrays, never world internals"). No wiring mechanism resolves this: the Model protocol has no slot for a world reference, and the registry/factory interface takes none.

NC-2 — No mechanism specifies which training-region fx-brittle uses across multiple worlds

1 panel, high-confidence architectural reasoning

No mechanism specifies how a single registered fx-brittle instance would select the correct training-region box when run against both worlds (LV and pendulum have different boxes and different state dimensionality). predict(state, action) carries no world identifier.

NC-3 — The two flagship Round 3 fixes are mutually exclusive

1 panel, directly follows from NC-1/NC-2

The only layering-preserving fix to NC-1 — harness-side construction-time injection — requires harness.trials to reference fx-brittle's specific class/function name, which is exactly what the new TC-MU9-01 AST-walk (added this round) is designed to fail on. The two flagship Round 3 fixes are mutually exclusive on the one real fixture that exercises both.

NC-4 — Exception-unsafe cleanup writes to production directory

2 independent panels

The new test_registry_isolation.py mechanism has no exception-safe cleanup, and because its stub file is written into wmj/models/ — the actual production discovery directory, not a scratch location — a failed test run (which the design's own text says can happen) can leave a phantom model that a subsequent real wmj run auto-discovers and executes.

NC-5 — fx-brittle corruption trigger incomplete

2 independent panels, converging with a 3rd from a different angle

fx-brittle's corruption trigger checks only the state sub-box, not the action interval, even though WD-5/ADR-W4 defines out-of-region as state-outside-box or action-outside-range — contradicting the fix's own claim of "no possibility of disagreeing" with the harness's region labelling.

NC-6 — New AST checks both use disproven "enumerate call shapes" technique

4 independent panels, 2 distinct evasion sets found

The two AST checks added this round (exec/eval ban, numpy.random.* ban) both use "enumerate call shapes," which the same document's TC-NF6-03 (added in the same round) explicitly says is insufficient and replaces with "ban the name outright." Concrete evasions: from numpy.random import rand; rand(); e = eval; e(...); __builtins__.__import__(...)/__builtins__.eval(...) (neither check names __builtins__); compile() + executing the resulting code object (named by no check at all).

NC-7 — Implementation guide wiring matrix describes disproven mechanism

5 independent panel-runs

implementation-guide.md's Wiring Matrix still describes TC-MU9-01's enforcement as "the named tests/gates/test_registry_isolation.py git-diff mechanism, design-review-002" — the exact mechanism cross-cutting.md v1.3 explicitly says was replaced because it was "structurally incapable of failing." A builder following this row would rebuild the disproven mechanism.

NC-8 — Ten test cases never wired to any build chunk

1 panel, mechanically verified: 0 matches on grep

implementation-guide.md never wires 10 of the suite's 79 test cases to any build chunk, including TC-JU3-01 — the sole test for JU-3, a Must requirement, unwired since Round 1 (not a Round 3 regression; a pre-existing gap only now surfaced by explicitly checking build-plan/test-suite reconciliation).

NC-9 — Critical path still wrong a third time

2 independent panels, from-scratch recomputation both times

The "corrected" 9-chunk critical path (Round 3's own fix) is still wrong: a third branch (P2-C05 → P3-C02) ties for longest path into P6-C01, but the guide's Dependency Network table labels P2-C05 itself "not on critical path" — a direct internal contradiction.

NC-10 — BC-1 recurred: schema blocks still not unified

1 panel, mechanically verified: 4th consecutive round of the same shape, promoted to BC-1

calibration/sharpness — the blocks Round 3 itself restructured this round — still use _in_region/_out_region field-name suffixes instead of an explicit region key, contradicting the same round's own change-note claim of "matching every sibling block." error_vs_horizon was left with no task dimension at all.

NC-11 — Undisclosed CI dependency contradicts architecture

1 panel

NF-4's disclosure describes a "CI" re-run of the confidentiality scan as an existing enforcement layer; no CI system is built, configured, or even listed anywhere, and architecture-overview.md's own System Context explicitly states "no other external systems... no network, no services" — a claim Round 3 re-certified with "no new conceptual-integrity finding" in the same round this contradiction was introduced.

NC-12 — GitHub push-timestamp mitigation has undisclosed dependencies and decay window

2 independent panels

The GitHub push-timestamp mitigation added this round for prereg-timestamp forgery introduces an undisclosed network dependency (contradicting the "no network" architecture claim), has no specified fail-open/fail-closed behavior, and — per Panel E-calibrated's research into GitHub's actual API retention — silently degrades to no protection at all for any prereg commit older than GitHub's ~90-day Events API window, with no disclosure of that decay.

New Findings — Important

NI-1 — Registry return contract unspecified

3 independent panels

wmj.models.registry.all_models()'s return contract (factories? instances? what shape?) is never specified, despite being the sole MU-9 discovery mechanism and having a named consumer (harness.trials) three times in the Wiring Matrix.

NI-2 — No test proves registry is actually called

2 independent panels

No test proves harness.trials actually calls all_models() rather than maintaining a separately-hardcoded roster that happens to agree today — the two-path-divergence risk the calibration prompt asked about directly.

NI-3 — No canonical model name pinned

1 panel, positively confirmed absent

No canonical name string is pinned for either baseline or the matched unrigged pair, despite MU-2/JU-2/MU-5 all requiring the harness to identify specific models by name — and no test (including the new TC-MU9-01) could catch a mismatch, since it only exercises an arbitrary throwaway model.

NI-4 — No duplicate-name check in registry

1 panel, positively confirmed real

No duplicate-model-name check exists in register() — two submodules registering the same name would silently collide, violating the project's own "fail loudly, never partially" convention.

NI-5 — Mid-process file creation may need cache invalidation

2 independent panels, converging via different technical routes

pkgutil.iter_modules's interaction with mid-process file creation (TC-MU9-01's own stub-write step) likely needs importlib.invalidate_caches(), and/or raises an idempotency question (a deleted stub file's registration may persist in-process) — neither addressed anywhere.

NI-6 — AST gate scope narrower than its credited coverage

1 panel

ADR-002 rule 3 credits the AST gate as enforcing "no ambient inputs" across worlds, models, and judge, but the gate is textually scoped to wmj.judge only — worlds/models have no structural enforcement, only empirical byte-identity tests that wouldn't catch a stable-but-wrong ambient read.

NI-7 — Region labels fix claimed but never applied

1 panel, mechanically verified

region_labels is claimed "unified across all three domain specs" but worlds.md's own version banner is still v1.2 with no changelog entry for it — the claimed fix was never actually applied there, only referenced in prose.

NI-8 — axis value set disagrees between two defining documents

1 panel

axis's value set disagrees between the two documents that define it: worlds.md's ADR-W4 defines a 3-value enum with no null case; judge.md cites ADR-W4 as the source for a 4th value (null) that ADR-W4's text never states.

NI-9 — Trial count ambiguity threatens runtime budget

1 panel

JU-8's N=200 trial count is ambiguous as to whether it multiplies per (region, task) — a 2–4× difference that could blow NF-2's 600-second runtime budget depending on which reading is correct.

NI-10 — natural_units has no defined value for pendulum

1 panel

JU-7's natural_units field has no defined value for the pendulum (which has no natural period, unlike LV) — the schema's only worked example is LV-only.

NI-11 — Chart 2 caption template violates its own acceptance test

1 panel, mechanically verified: 4 sentences, RP-5 requires 2-3

Chart 2's own authored caption template violates RP-5's sentence-count requirement and would fail its own acceptance test (TC-RP5-01) on day one.

NI-12 — NF-4 historical-blob scan misses reflog content

1 panel

The NF-4 historical-blob scan (git rev-list --objects --all) doesn't reach reflog-only-reachable content (amended/rebased/reset-away commits) or dropped/popped stash entries — the same permanence argument that motivated the scan applies to these, unaddressed.

NI-13 — Pre-existing core.hooksPath setting defeats hook activation

1 panel

The .githooks/pre-commit activation depends on core.hooksPath being set correctly; nothing checks whether a pre-existing, unrelated core.hooksPath setting (common with other tooling) silently defeats it — a silent, undetectable failure mode distinct from the disclosed "never configured" gap.
