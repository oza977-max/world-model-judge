Critical Findings

C1 — The load-bearing purity control is defeated one layer down; BC-4 is now confirmed, not a candidate

Panels: E-calibrated (3/10), E-blind (3/10) — convergent, both with executed exploits.

Files: specs/cross-cutting.md ADR-002 rule 3; specs/judge.md §4; test-cases/test-cases.md TC-JU12-01.

The v1.6 mutate-in-place fix closes the specific escape Round 6 found (confirmed by execution — the guard fires on np.get_include.__globals__['os'].getcwd() and on np.datetime64('now')). But both panels then exhibited new accidental-impurity routes that escape the exact pinned harness, with running code:

  • os.environ is rebound, not mutated in place (E-cal F1). The pinned text says os.environ → a raising proxy — a reassignment. Any name bound to the real _Environ before the guard installs (ENV = os.environ at module load — an everyday idiom) sails past. This is the identical rebind-vs-mutate bug class v1.6 was commissioned to fix, one level down. Executed: _CAPTURED_ENVIRON.get('HOME') → '/root', ESCAPE. The correct fix (mutate the real _Environ instance's bound methods) was proven to close it.
  • numpy.random legacy globals are the threat model's own example, and escape (E-cal F3, E-blind). "Legacy globals" is a category label, not the mtrand._rand singleton. np.random.normal() and np.random.uniform() — ~40 free functions routing through the hidden singleton — run uncaught. The threat model names "a numpy.random call that varies between runs" as precisely what it protects against.
  • Unenumerated os attribute surface via reflection (E-cal F2). os.getpid(), os.urandom(), os.listdir(), os.sys.modules['random'].random() all escape — reachable through the same __globals__ route, one hop past the very object the guard patches. "Trips however the code reached it" is true only for the four named attributes.
  • ctypes is already resident via numpy — no import for any check to see (E-blind, CRITICAL). 'ctypes' in sys.modules is True the moment numpy imports. A ctypes.CDLL(None) call performed a real wall-clock read and a real /etc/hostname read, bypassing every guarded Python object.
  • Unseeded Generator(PCG64()) reaches getrandom() with no Python object in the path (E-cal F4). Traced with strace: getrandom(...) = 16. Generator.__init__ is a C immutable type and cannot be monkeypatched at all (TypeError). The "mutate the shared object in place" strategy is architecturally inapplicable here — and ADR-002 rule 2 names this exact constructor as the sanctioned seeding pattern, so an author who forgets the seed argument produces silent nondeterminism this control cannot detect by any variant of its own mechanism.

Why this is the fork and not a patch: the universe of ambient-capability objects reachable from a CPython process is exactly as unbounded as the universe of import statements was when the static gate was demoted. Enumerating more targets chases the disease. The honest options are (a) narrow what JU-12 claims — the runtime harness catches the common accidental routes, byte-identity across runs (NF-1) is the actual backstop, and the "complete" / "load-bearing" language is dropped in favour of "best-effort + empirically backstopped + disclosed"; or (b) move purity enforcement out of process — run the judge in a subprocess under an OS sandbox (seccomp/namespaces) that actually intercepts getrandom and ctypes syscalls, a substantial architectural change. This is the user's call, not the review's.

C4 — The "models never import harness" invariant is enforced by no gate, in the one direction that matters

Panels: C-calibrated (4/10) F4, C-blind (6/10), F2-calibrated (5/10) F1 CRITICAL — convergent.

Files: specs/cross-cutting.md ADR-003; specs/models.md ADR-M1 §4.

The whole SeedSource-in-models.base redesign is justified by "so fixtures can derive direct's stream without importing the harness." But TC-NF6-07 only checks models→worlds, and TC-MU9-01(c) checks judge/worlds/reporting/harness → models — nothing checks what wmj/models/* imports outward toward wmj.harness. Stated as settled fact with no disclosure — a break in the project's own honesty discipline. Compounded (C-blind): wmj.models.base now hosts a general seed utility consumed by the harness for non-model purposes, so the package's declared responsibility and its contents no longer match. Fixable (add the symmetric AST gate; consider whether SeedSource belongs in a neutral module).

C5 — The harness orchestration loop and the judge's per-region trial partitioning have no design anywhere

I3 — The model_ref-shift disclosure promised in Round 6's own remediation plan was never written

F1-calibrated (6/10) F5. Round 6 finding I7 ("model_ref shifts on roster change, undisclosed") appears in the remediation plan; v1.6 wrote only the positive "reproducible across machines" claim, true only within one fixed roster, with no caveat and no changelog entry and no test. A promise the process caught and then dropped silently — worse than a missed bug. Fixable (add the disclosure).

I4 — component_key's colon-join is not injective; "provably never shifts" overclaims

F1-calibrated F2, F1-blind MAJOR — convergent, both executed. ":".join(...) has no delimiter escaping: component_key('a:b','c') == component_key('a','b:c'), identical RNG streams. Dormant today (no current part contains :) but the "provably never shifts any other component's stream" language is stronger than the function proves — it holds by luck of the current vocabulary, not by construction. Fixable (reject : in any part at construction with a loud error, or length-prefix each part; or state the reserved-character restriction as part of the pinning).

I5 — is_baseline's "adding a baseline is one file" overstates what the flag delivers, and has zero test coverage

F2-calibrated F4, F2-blind F1, A-calibrated. The flag's only consumer is prereg-exemption (not is_baseline and not is_fixture). A new is_baseline=True model trains and is judged like any contestant but can never become a reference others are compared against — the Verdict schema hardcodes exactly vs_persistence/vs_linear, and the blind judge cannot extend it. "Exactly as a fixture does with is_fixture" invites the wrong expectation. Also: no test registers an is_baseline=True model and asserts check_prereg skips it — the specific Round-6 bug the flag was invented to fix has no regression test. Fixable (one honest sentence scoping the flag; add the coverage test).

I6 — SVG chart output is not byte-reproducible by default, undisclosed

F1-blind MAJOR, executed. ADR-R1 markets SVG as the byte-diffable reproducibility artifact for a sceptic. matplotlib embeds a real-time <dc:date> and random element IDs (uuid4() salt) per render — two runs differ. Fix verified: pin matplotlib.rcParams['svg.hashsalt'] and metadata={'Date': None}. As specified, every wmj verify SVG diff a sceptic tries fails, contradicting the one sentence written to reassure them. Fixable.

I7 — run-manifest.json's "package versions" field has no named source and two passages contradict

F1-calibrated F6. reporting.md's file-layout comment lists "package versions" in run-manifest.json; the Integration Points passage drops it, and envelope.meta's schema (seed, platform, prereg_commit, thresholds_file) has no such field. The one field most needing a deterministic capture mechanism for wmj verify's byte-comparison (RP-7) has no stated producer. Fixable (name importlib.metadata, reconcile the two passages).

I8 — check_prereg verifies commit order, not content-invariance; an ordinary second commit defeats pre-registration

E-blind HIGH, executed with real git. check_prereg asserts the prereg file's first-added commit precedes the run. Exhibited: a day-1 placeholder commit, then a day-243 commit writing matching_margin: 0.049 # tuned after seeing results — clean working tree, honest dates, no rewrite, no --amend. Both assertions pass; the content in force at judging time was written 8 months after the file first existed. This is exactly MU-6's stated enemy ("thresholds moved after seeing results are not thresholds"), it is not covered by ADR-M5's three named residual risks, and it is easier than any of them. Needs decision (disclose as a fourth residual risk honestly, or strengthen the check to a content-hash pinned at first commit).

I9 — TC-MU9-01(c)'s join-check is ambiguous on the import shape the harness needs, with no clean-pass guard

F2-calibrated F3, executed. A literal exact-match implementation of the pinned join rule false-positives on the legitimate from wmj.models.registry import all_models that harness/trials.py genuinely needs — a build-blocking false positive on day-one production code, with no clean-pass guard (unlike the judge's own gate, which has TC-NF6-06 precisely because "a gate that cries wolf gets disabled"). Fixable (add a clean-pass case pinning the allowed shapes).

I10 — MU-9 "one file" extensibility vs NF-2 runtime budget is an unacknowledged tradeoff

F2-blind F3. Every model added under the "one file" promise grows the 16M-call estimate the 600s TC-NF2-01 gate is budgeted against. Headroom is ~2 orders of magnitude so materiality is low, but the tradeoff is never stated. Minor-Important. Fixable (one sentence in ADR-J6).

Recommended disposition

Review's recommendation — user owns the decision:

Two clusters, and they should be handled differently:

Cluster 1 — mechanical, ~1 hour, execution-verified as before (recommend fix): C2, C3, C4 (add the gate), C6, I1, I2, I3, I4, I5, I6, I7, I9, I10, and the minors. Every one is a bounded edit with a demonstrated fix; several are just finishing v1.6 edits that overstated themselves.

Cluster 2 — the design fork, the user's call (recommend decide, do not patch):

  • C1 / BC-4: narrow JU-12's claim to "best-effort + empirically backstopped + disclosed," OR move purity enforcement to an out-of-process OS sandbox. The review recommends (a) for a toy-world harness whose own thesis is about honest disclosure of limits — dropping the "complete" claim and disclosing the residual is more in the spirit of JU-10 than an unwinnable enumeration arms race — but this is exactly the architecturally-significant decision Hard Gate 6 reserves for the user.
  • C5: write the orchestration-loop + JudgeInput-partitioning ADR (spec work, not a fork, but substantive).
  • I8: decide whether MU-6's prereg guarantee is order-only (disclose the content-drift gap as a fourth honest residual) or content-pinned (strengthen the check).

The review does not decide any of these. It records that the surface has converged, the mechanical cluster is finishable, and the one honest hard question left is what the judge's purity control can truthfully promise.
