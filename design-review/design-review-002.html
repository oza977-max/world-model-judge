World Model Judge — Design Review 002

Independent re-scanning of all seven specification documents with two new panel types (Security, Quality Attributes). Verification that Round 1's 26 fixes hold cleanly; discovery of 8 new Critical and 9 new Important findings.

Verdict

Verdict
Do not build

Round 2 confirms most of Round 1's fixes hold cleanly (16 of 26 verified CONFIRMED-RESOLVED), but strict independent re-scanning with two new defect classes (Security, Quality-Attribute scenarios) surfaced 8 new Critical and 9 new Important findings — a defect population comparable in size to Round 1's. Three of Round 1's own fixes proved only partially resolved, and one (the double-pendulum EOM) introduced a new, more dangerous defect: a coefficient error baked self-consistently into the reference test values, which the test suite as specified cannot detect. This is not a process failure — it is exactly what a genuine Round 2 is for.

Executive Summary

Seven independent panels scanned all specifications under strict, narrower criteria than Round 1. Five of Round 1's findings reappeared independently from different angles in different panels, confirming those findings' robustness. Two new panel types (Security, ATAM-driven Quality Attributes) revealed gaps the original four panels' lenses could not reach. Most significantly: two separate panels (F1 Reproducibility and E Security) converged independently on the same root mechanism being insufficient (the AST import-graph gate), examining it from different angles and finding two distinct loopholes — independence-convergence, the methodology's strongest available confidence signal.

The pattern of findings has shifted subtly but importantly from Round 1. Round 1's defects were primarily in specification incompleteness (missing field names, unstated constants, unnamed edge cases). Round 2's defects are in specification inconsistency: a required field omitted from a mandatory-list; a trust horizon that lacks a region axis, defeating the entire reason the region axis was added to other blocks; two different definitions of "exception" that the specification claims cannot disagree. This points to a process fix: when a fix touches a shared artefact (a schema, a total count, a formula), re-derive or recount it from scratch rather than trusting the delta was applied everywhere it's referenced.

Partially Resolved / Regressed (3 of 26)

C3 — Chart 1 (RP-1) per-trial data. The trials block was added, but two new gaps surfaced under strict re-scan (Panel B): a field-name mismatch inside reporting.md itself (outcome cited in one place, outcome_distance — the schema's actual field — in another), and the X-axis ordering rule requires a start-state-distance-from-region-centre value that doesn't exist anywhere in judge.md's schema, with reporting.md structurally unable to derive it (reporting "computes no metric of its own"). Panel C independently found a second angle on the same block: JU-9's mandatory-field list doesn't include trials or climatology, so verdict.py isn't actually required to refuse a Verdict missing them — undermining the fail-loudly guarantee for the one chart this fix was written to unblock.

C6 — Double-pendulum EOM. The hand-waving ("textbook equations") is gone — worlds.md §4.2 now states θ̈₁, θ̈₂, and E explicitly. But Panel D re-derived the equal-mass case from Euler–Lagrange and found denom1/denom2 and θ̈₁'s leading gravity term use coefficient 2·m where the correct general-mass formula (2m₁+m₂) specializes to 3·m. Because the spec states its own hand-verified TC-WD1-01 reference constants are computed from this exact formula, the bug is now self-consistently embedded in what the test suite treats as ground truth — the fix is confidently wrong in a way the original vague version could not have been, since nothing built against "textbook equations, unspecified" could have silently shipped a wrong constant.

C9 — Implementation guide sequencing. The core fix (P2-C05, a genuine second early real-chart slice) is sound and demonstrable — Panel D confirmed the chunk itself, its dependency wiring, and its Wiring Matrix row all check out. But the guide's own chunk-count bookkeeping is wrong (28 actual chunks, not the "24" stated four separate times), and the guide's claim that P2-C05 "shares no files with any Phase 3 chunk" is false: both P2-C05 and P3-C02 target wmj/models/baselines.py per the models.md component design and the guide's own Wiring Matrix naming, and running them in parallel as explicitly recommended would produce a merge conflict or silent overwrite.

Part 2 — New Findings

Critical (8 new)

NEW-C1 (Panel A) — The NF-4 confidentiality-scan mechanism instructs a maintainer to commit the exact secrets NF-4 forbids

scan_repository() walks tracked files via git ls-files, and wmj/harness/confidentiality.py — the module implementing the scan — is itself one of those tracked files. The spec's own remediation instruction ("the actual private seed list … is added to this file directly") tells a future maintainer to write the literal forbidden term into a Python string constant inside a file that will be committed to a public repository with, per CLAUDE.md, "no window in which a mistake could be quietly fixed." Following the ADR exactly as written causes the violation it exists to prevent. Compounding: FORBIDDEN_TERMS is currently an empty list, so the scan can never find a match and passes vacuously regardless of repository contents — the one gate this project calls out as having "real, checkable teeth" currently has none, and cannot get any without the self-defeating step above.

NEW-C2 (Panel C) — trust_horizon carries no region field, defeating the project's own headline mechanism

judge.md's trust-horizon formula and Verdict schema (trust_horizons.per_task) have no region axis, unlike exceptions.per_task and error_vs_horizon, which do (and which the v1.1 changelog says were fixed for exactly this reason). But fx-brittle exists specifically to be "great at home, catastrophic away — only the in/out region split surfaces it" (MU-3/ADR-M4). Without a region-conditioned trust horizon, the headline comparison table (RP-4) — the metric this project's own fixture roster was built to demonstrate — cannot show the phenomenon it exists to reveal.

NEW-C3 (Panel C) — JU-9's mandatory-field list omits trials and climatology, undermining fail-loudly for the primary chart

judge.md §5 names six mandatory field groups explicitly, excluding the two newest top-level blocks. This directly contradicts cross-cutting's own Error-Handling rule 1 ("a required verdict field that cannot be computed → the run aborts; no partial record is written") and risks the exact failure mode Round 1 was trying to close: RP-1, a Must-requirement chart, silently undrawable with no abort.

NEW-C4 (Panel D) — Double-pendulum equations of motion contain a coefficient error

See C6 above (Part 1). Listed here as a fresh, independently-derived Critical finding in its own right: a physics bug in the ground-truth generator, embedded self-consistently in the test suite's own reference values, undetectable by any test in the current design.

NEW-C5 / NEW-C6 (Panel B) — Chart 2 and Chart 3 each need a data field the schema doesn't carry

Chart 2 (RP-2) requires a grey baseline error-vs-horizon curve; error_vs_horizon's schema has no baseline field, and reporting "computes no metric of its own" so cannot derive one. Chart 3 (RP-3) requires N (sample size, N=200) to compute binomial standard-error bars; the calibration schema block carries no such field, forcing either an undeclared hardcoded duplicate of ADR-J4's constant or a boundary violation of reporting's own "no metric computed" rule. Both are the same defect class as the original C3 finding (a Must-requirement chart needing data the schema doesn't supply), recurring on two more of the four required charts.

NEW-C7 (Panel F1) — The only described purity-enforcement gate doesn't catch ambient reads

cross-cutting's AST-walk gate (test_import_graph.py) is scoped to block wmj.* imports inside wmj.judge — it says nothing about os, time, sys, or similar direct ambient reads. Same-machine repeated-run tests (TC-NF1-01) would not reliably catch this class, since an ambient read (e.g., a working directory or hostname) is often stable across ten consecutive runs on one machine while still violating NF-1's explicit cross-machine scope.

NEW-C8 (Panel E) — The same gate also misses dynamic imports

Independently, Panel E found that importlib.import_module("wmj.models") called from inside wmj.judge would not trip the AST-walk gate as described (it scans Import/ImportFrom nodes, not arbitrary function calls), giving JU-1/JU-12's blindness guarantee a second, distinct bypass route through the identical mechanism.

Note: NEW-C7 and NEW-C8 are listed separately because they are different loopholes, but both indict the same single mechanism — see Cross-Panel Themes.

Cross-Panel Themes

1. The AST import-graph gate is the sole described enforcement of judge-purity, and two independent panels found it insufficient from two different angles

NEW-C7 (ambient reads) and NEW-C8 (dynamic imports) converged independently from unrelated panels examining the gate for different reasons. Per this methodology's confidence rule, independent convergence from unrelated panels is the strongest available signal — this is not two guesses, it's the same weak point found twice by people looking for different things.

2. The trials block, added in v1.1 specifically to unblock RP-1, is still not fully wired

Panel B found it from the interface-contract angle (field-name mismatch, missing X-ordering source data) and Panel C found it from the structural angle (missing from JU-9's mandatory list, disagreeing definition of "exception" with the older exceptions block). The block exists, but three of four panels who could have touched it found a different way it doesn't yet close the loop.

3. A pattern of "the fix removed the vague version but replaced it with a wrong precise one" appears twice

The double-pendulum EOM (hand-waved → precisely, confidently wrong) and the chunk count (an honest "we added one chunk" claim → a wrong arithmetic total asserted four times). Precision without a recount is not the same as correctness.

What Prevents a Higher Score

The same root cause as Round 1, recurring: specification precision is uneven across the same document. Sections that were the direct target of a named Round-1 finding (z_p, training constants, fixture formulas) are now airtight — independently re-derived and verified correct. Sections that were touched only as a side effect of a Round-1 fix (the trials block's mandatory-field status, the pendulum EOM's actual coefficients, the chunk-count arithmetic after adding one chunk) were not re-verified with the same rigour, and each has a genuine defect.

This suggests a process fix worth naming for future rounds: when a fix changes a shared artefact (a schema block, a total count, a formula), re-derive or recount that artefact from scratch rather than trusting the delta was applied correctly everywhere it's referenced.
