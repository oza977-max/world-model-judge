Critical Findings

C1 — The runtime purity harness (the v1.5 load-bearing control) does not work as specified. CONFIRMED BY FOUR PANELS, THREE WITH RUNNING CODE.

E-cal (executed), E-blind (executed, quantified: 8 numpy submodules already hold a pre-bound os reference before any test runs), D-cal (by inspection), F2-blind (executed).

v1.5 demoted the static AST gate to lint and made TC-JU12-01 the load-bearing purity control, specified as "replace the os module in sys.modules with a raising guard." But swapping the sys.modules entry only changes what a future import os resolves to — numpy bound its own os reference at numpy's import time. The old Round-5 escape survives verbatim:

np.get_include.__globals__['os']

This still returns the real, unguarded module. Consequently TC-JU12-02 (the phantom-gate) would fail its own assertion — the fix doesn't satisfy its own new test. Right now, with the static gate correctly disclaimed as lint, JU-12 purity has no working enforcement control. The fix is known and demonstrated by three panels: mutate the shared object's attributes in place instead of reassigning sys.modules:

setattr(os, 'system', raising_proxy)
setattr(os, 'environ', raising_proxy)

The spec conflates the two techniques as if interchangeable ("patched in sys.modules / the real builtins"); only mutate-in-place works. E-blind's defense-in-depth note: the static lint and the runtime harness fail for the same reason (pre-existing module state), so the "two layers" are one point of failure for this class. Category: REGRESSION (v1.5's own fix).

C2 — The NF-4 confidentiality scan command searches nothing.

E-cal, executed.

The committed command:

git cat-file --batch-all-objects --batch-check

This emits only <sha> <type> <size> per object — never content, for blobs or commits. So TC-NF4-01 passes green regardless of what forbidden terms sit in history, on the requirement CLAUDE.md calls "absolute." The fix is simple:

git cat-file --batch-all-objects --batch

E-cal demonstrated the working form. Category: REGRESSION (v1.5's own NF-4 edit).

C3 — component_key's hash is an example ("e.g."), not a pinned algorithm.

F1-cal + F1-blind (both executed diverging readings) + D-cal.

The spec says "a fixed, documented hash, e.g. blake2b(":".join(parts), digest_size=8)"; F1-blind executed four textually-conforming readings that produce different Generator streams from the first draw. Two spec-conforming builds are byte-different — impossible to independently verify a published seed from the document, in a project whose mission is independent verification. Fix: replace "e.g." with the mandated construction; pin digest→int mapping and how index folds in. Category: NEW (the v1.5 seeding fix pinned the outer SeedSequence ordering but left the inner hash illustrative).

C4 — The seed key has no "purpose" discriminator; training/eval/benchmark start-sets can collide.

F1-blind.

The content-addressed key enumerates only {model, world, region, trial-index}. Three independent random draws — MU-7 training-trajectory starts, JU-8's 200 evaluation starts, WD-4's 64 benchmark starts — are all "per (world, region)"; for the training region they key to the same seed. Naive-but-conforming build makes eval starts coincide with training starts, defeating MU-7 disjointness and JU-8's independence-of-trials (the entire N=200 binomial-band derivation rests on it). Fix: add a purpose/consumer field to the key. Category: NEW.

C5 — The Verdict schema's worked example self-contradicts the one-Verdict-per-(model,world) contract.

C-blind.

The example fixes "world": "lv" but its trust_horizons.per_task lists a dp-control (double-pendulum) entry. Five rounds rewrote this exact block and never caught it. A builder can't tell whether a Verdict carries cross-world data or the example is wrong. Category: NEW (latent since v1.1).

C6 — The v1.5 h_task pin reworded skill.per_task_region's step, contradicting "one-step" (h=1) used by MU-5's matching margin and three test cases.

B-cal.

The same block×axis pass that correctly pinned calibration/sharpness to h_task glossed the skill row as "the step is fixed by the task" — which reads as h_task, not h=1. But MU-5's matching margin (TC-MU5-01), TC-MU2-02, and TC-JU2-01 all need a literal one-step (h=1) skill score, and the project's headline "ordinary error ranks them equal, the judge does not" claim rests on that margin. Fixing two blocks while breaking a third adjacent one, same table, same pass. Category: REGRESSION (v1.5's own fix).

C7 — The fixtures' "bit-identical direct core via the same content-addressed seed" is unbuildable through the sanctioned channel.

C-cal.

The seed derivation lives in wmj/harness/seeds.py; the fixture factory receives only its own (ctx, rng, training) and has no authorized, gated channel to obtain "direct"'s seed (models→harness is neither sanctioned nor covered by TC-NF6-07). The only builds are an ungated models→harness import or duplicating the hash in fixtures.py — both defeating the fix's own intent. TC-MU4-02's weight-identity claim is unbuildable as worded. Category: NEW (a second unbuildable-model problem behind the C6 fix v1.5 claimed closed).

C8 — TC-MU9-03 (the CLI-path test v1.5 added) is unbuildable-as-worded or a lookalike.

F2-blind + F2-cal.

The stub graft is an in-process wmj.models.__path__ monkeypatch; a genuine python -m wmj run subprocess starts a fresh interpreter that can't see it, so the test fails whether the CLI is wired right or not; the in-process reading is a weaker lookalike. It also collides with the full-pipeline cost, the ModelContractError fail-loud path, and (per C9) check_prereg. No roster-dump/--dry-run seam is specified. Category: NEW (v1.5's own addition — the test meant to close Round-5's "CLI holds its own list" gap).

C9 — ADR-M5's "adding a baseline remains one-file" is contradicted by its own classification rule.

F2-cal.

v1.5's honest-scope fix classifies a model as unrigged iff it is neither a pinned-baseline name nor is_fixture. But there's no structural "baseline" marker — only a hardcoded name pair. A genuine new baseline would be misclassified as unrigged, routed through check_prereg, and blocked, forcing a second-file edit the same paragraph says is unnecessary. Category: NEW (v1.5's own fix).

C10 — Three test cases wired to chunks that structurally cannot satisfy them.

D-blind (satisfiability check, deeper than the A panels' presence check).

TC-WD3-01 → P1-C03 (its ground-truth generators, benchmarks/training-data, don't exist until P2/P3); TC-NF3-01 is a true orphan (only "groundwork," never a real [Test:] tag, though P6-C02 builds its gate); TC-MU2-01 → P3-C02 (no judge verdict logic there). Category: BC-3 recurrence (my v1.5 reconciliation left these; note I rewrote TC-WD3-01's content but left its placement).

The Meta-Finding, for Triage

The Design Converged; Failures Are in Mechanism Precision

Six rounds, six "Do not build" — but the trajectory finally turned.

  1. The design converged. The schema, the interface contracts, the coverage, the critical-path arithmetic, and three of the v1.5 design decisions (content-addressed seeding, the registry teardown, the import-join) are all verified clean or working by execution. Panels that scored 2–3 for five rounds scored 6–9 here. That is real.
  2. The failures are now in mechanism-specification precision, not architecture — two clusters, both with known small fixes:
    • The purity/scan mechanisms (C1, C2): mutate-the-shared-object-in-place instead of swapping sys.modules; guard numpy's clock; --batch not --batch-check. These are ~5-line corrections to text, demonstrated by the panels.
    • The determinism/precision layer (C3, C4, ensemble K=5, model_ref, platform): pin component_key's hash, add a purpose key, spec the ensemble split, disclose the model_ref shift, name the platform string.
    • Plus a handful of prose/wiring fixes (C5–C10) — several of which v1.5 introduced.
  3. The v1.5 "fix all" pass planted five of this round's ten Criticals (C1, C2, C6, C8, C9) — done at speed and self-verified, exactly the BC-2 failure mode. But this round also proves the underlying decisions were sound; the defects are in how the mechanisms were written down, caught precisely because this round pressure-tested them with running code instead of prose.

If the two mechanism clusters are fixed — this time with independent execution-based verification rather than self-verification — Round 7 could plausibly clear. This is the first round where "Do not build" comes with a short, concrete, mostly-mechanical path to "Build with caveats," not another structural rethink.
