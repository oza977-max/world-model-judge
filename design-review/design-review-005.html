Critical Findings

C1 — The judge-purity AST gate is defeated by Python reflection; its named runtime backstop is structurally blind to it.

Convergence: E-blind, E-calibrated (three evasions executed against live Python 3.11 / numpy 2.4.6), F2-blind (executed).

The allowlist + banned-identifier + numpy.random checks are all evaded, with no import and no banned identifier, by:

().__class__.__base__.__subclasses__()
np.get_include.__globals__['os'].system(...)
getattr(np, "__builtins__")["eval"]

The spec's own stated closure ("realistic indirection routes close") considered only getattr(builtins,...)/getattr(__builtins__,...) written as code — not __globals__ reads or __subclasses__() walks, and its own canonical Given/When/Then (test-cases.md) never mentions an import hook at all. TC-JU12-01, named as "final runtime authority," intervenes only on new imports and builtin-name poisoning — neither touches __globals__ reads or __subclasses__() walks. This is the deepest finding of the round. It is not a fifth instance of the enumerate-evade-patch cycle — it is the demonstration that no finite identifier list closes attribute-graph reflection in Python. Category: NEW class.

C2 — The import allowlist checks the module name, not the capability surface.

E-blind, executed.

np.fromfile("/etc/hostname") and np.datetime64('now') reach the filesystem and clock through the allowlisted numpy module; the AST check inspects only the top-level module name. ADR-002 rule 3 claims the judge gets structural (not merely empirical) ambient-input enforcement and contrasts this with worlds/models' empirical-only enforcement — this exhibit shows the judge has exactly the same empirical-only weakness. Category: NEW.

C3 — The determinism claim has no pinned seed-derivation mechanism.

Convergence: F1-calibrated and F1-blind, both executed.

ADR-002 rule 2 says "component seeds are derived from one run-level seed via PCG64 jumped/spawned streams so adding a component never shifts another component's stream" — but "jumped" and "spawned" are two different, non-interchangeable NumPy APIs (verified: different outputs from the same seed), no document says what a "component" is or in what order it is seeded, and the implementation most consistent with the project's own sorted-name/model_ref conventions (positional spawn over all_models()) was shown with running code to reassign every model's stream — hence weights, hence verdicts — when one alphabetically-earlier model is added. That silently defeats MU-9's headline "adding a model touches nothing else" at the trained-artefact level (true only at the source-diff level TC-MU9-01 checks), and no test in the 79-case suite would catch it. Category: NEW.

C4 — Two mandatory Verdict fields (the JU-10 limitations disclosures and the not_tested list) never reach the human-facing surface.

Convergence: B-blind and C-blind.

reporting.md's own Expert Panel assigns Mitchell the mandate "the not-tested list rendered as a first-class output, not a footnote," and architecture-overview.md says Dev reads results.html; yet neither limitations nor not_tested appears anywhere in reporting.md's four charts, caption templates, or results.html assembly. The project's core honesty requirement (CLAUDE.md: "every verdict states the judge's own limits") exists only inside a JSON file Dev is never told to open. Category: NEW.

C5 — WorldContext does not carry the scale vector direct/ensemble need, so 2 of the 7 models (plus the 3 fixtures wrapping Model A) are unbuildable through the "one sanctioned channel."

C-calibrated.

ADR-M3 says the MLP normalises (state, action) "by the world's scale vector"; that vector is not one of WorldContext's five fields, and §6 states WorldContext is the sanctioned channel with no exceptions. The only legal alternatives are to import wmj.worlds (the exact violation the repair closed) or leave the models unbuildable. Because fx-brittle must compare raw state/action against ctx.training_state_box, inputs to predict() are raw, so the normalisation genuinely needs a scale WorldContext lacks. Category: NEW, on the flagship repair group.

C6 — There is no training/fit entry point anywhere in the pinned model interface.

C-calibrated.

ADR-M1 ("the interface, complete") lists only name, is_fixture, reset(), predict(); factory(ctx, rng) receives no training data; ADR-M2/M3 require a fit step over the training dataset before predict() is meaningful. No module owns weight persistence, no format/path is specified, and the only textual gesture is a five-word field comment ("for weights-file keying"). Six of seven models cannot reach a ready-to-predict state through the described interface. Category: NEW, larger in scope than the fixture-only problem the repair solved.

C7 — TC-MU9-01 mechanism v3 corrupts the shared in-process production registry.

Convergence: F2-blind and F2-calibrated, both executed, two failure modes.

Restoring wmj.models.__path__ does not clear sys.modules['wmj.models.<stub>'], so a second same-named stub is served the first's cached module and its register() never runs; and the "registry snapshot-and-restore" the spec names, if it actually clears the stub, wipes the real persistence registration permanently when TC-MU9-01 is the first all_models() call in the process (the seven real models register lazily, so the setup snapshot is {}). This is quieter than Round 4's phantom-file bug — no artefact on disk, just a short roster in whatever test runs next. Category: REGRESSION-class (BC-2): the repair fixed the disk-write leak and left/introduced an in-process one.

C8 — The "models never import world internals" rule — which drove the entire WorldContext ADR — has no enforcing gate.

Convergence: A-calibrated, C-blind.

Every AST gate points the other way: TC-NF6 walks only wmj.judge; TC-MU9-01(c) checks that others don't import wmj.models. Nothing checks that wmj.models doesn't import wmj.worlds. A developer could write from wmj.worlds.lv import SCALE in fixtures.py and no test would fail — the project's own "enforced by test, never by convention" doctrine unapplied to the one claim a repair was built around. Category: NEW.

C9 — BC-1 recurs inside the BC-1 repair: calibration/sharpness's horizon-step axis is unverifiable against its own defining ADR.

B-calibrated.

The block×axis table asserts calibration does not vary over horizon_step (marked "—"), while its own "Why" cell says "at the task's declared steps" (plural) and ADR-J2 says "each task evaluates it at its own declared horizon steps." ADR-J3 (sharpness) never says which step the 90%-width is averaged over. A builder cannot tell which slice of the [n_trials, H, d] array to compute over — the exact ambiguity the canonical keying rule was written to end, in the one row not cross-checked. Category: REGRESSION (BC-1, 5th round).

C10 — Every specs/*.html twin is three rounds stale, showing disproven contracts to any reader who opens them.

Convergence: B-calibrated, C-calibrated, D-calibrated.

The .md sources are v1.4/v1.3; the committed .html are all v1.1, carrying register(factory) (the superseded single-arg signature) and "eight registered contestants" (the disproven roster). None carries the generated-from parity comment the mechanism (unbuilt) would need. architecture-overview.md itself says "if you read only one spec, read this one" — legitimising the HTML reading path. Category: NEW (a live instance of the drift the unbuilt parity check was designed to prevent).

C11 — Chart 2's world-time axis has no data source, and Chart 4 ranks on raw CRPS with the skill fields having no consumer.

B-blind.

error_vs_horizon.per_region carries only a step index — no dt, which is world-owned and which reporting has no import path to; yet ADR-R2 mandates a "world time" second axis. Separately, ADR-J1 says "no absolute error is ever emitted without its skill counterpart," but Chart 4 (RP-4, "the headline result") ranks by one-step CRPS and vs_persistence/vs_linear appear on no chart anywhere. Category: NEW (same schema/consumer class as design-review-002's Chart 2/3 fixes, not caught for these two spots).

C12 — TC-WD3-01 still asserts a property the architecture declared impossible.

A-blind.

The case requires a check that a model "used the identical integrator class"; worlds.md's own v1.1 fix (four rounds ago) states no model under test calls an integrator, and rewrote the WD-3 gate to model dt-alignment. The test was never updated, despite test-cases.md being revised in this same repair session. Category: NEW (stale test).

C13 — Implementation-guide wiring: three of the ten newly-wired cases are defectively placed, plus the MVP-1 second slice overclaims.

Convergence: A-calibrated, D-blind, D-calibrated.

TC-JU9-03 is wired to P4-C01, which has no exceptions/trials computation to exercise the invariant (belongs at P4-C04/C06); TC-MU1-03 (the reset-leak regression test) is wired to Model A, which structurally has no rollout-local state to leak — a vacuous pass; TC-NF5-02 tests the spec-parity gate against the repo's actual HTML, which was never regenerated, so it fails permanently; P2-C05's acceptance test requires the verbatim ADR-R3 caption, which narrates a switch-step feature sourced from climatology.per_task — a field first computed twelve chunks later — so the MVP-1 second slice ships a caption that overclaims relative to the image (in the project whose NF-5 forbids exactly that). D-blind additionally found baselines.py has contradictory owners (P1-C02 vs P2-C05), the training-data count N and epoch count are unreachable from the chunks that need them, and P2-C05/P5-C01/C03 share reporting files with no ordering edge. Category: BC-3 partial recurrence ("reconciled ≠ correct").

The Meta-Finding, for Triage

Architectural Questions Revealed by Executable Adversarial Review

Four rounds found finding-sized surface defects and patched them; the structural repair finally cleared that surface. What Round 5 then reached, with executable adversarial review, is a different and deeper layer:

  1. The judge-purity gate (C1/C2) may be structurally unable to deliver what it promises. A static AST allowlist cannot bound Python's reflection graph; the named runtime backstop is the wrong shape. This is an architecture decision, not a patch: either the judge is restricted to a genuinely non-reflective style enforced some other way, or TC-JU12-01 becomes the sole real control and must be specified to intercept attribute/dict access, not just imports and builtins — or the purity property is downgraded from "structural" to "empirical + disclosed," matching what the gate can actually deliver.
  2. The model-provisioning interface (C5/C6) is underspecified in a way no chart-or-schema fix reaches — there is no training channel, and the "one sanctioned channel" doesn't carry a fact two models need. This is the models spec's core interface, not its edges.
  3. The determinism guarantee (C3) has no pinned mechanism for the one thing NF-1 exists to protect.

These three are not "fix the finding" items; they are "decide the design" items. The recurrence pattern (BC-1/2/3 each re-appearing in the round assigned to close them) continues, but now alongside genuinely-cleared prior defects — which is the first evidence that the repair changed the kind of finding, even though it did not change the verdict.
