The first review after real construction. What this round found

Nine independent reviewers read the specs and executed the build evidence each backlog row cites. The blind determinism panel re-ran the real pipeline at the production seed rather than trusting any claim. Three things stand out:

  • The corrections are real and the fixes are right. Every A-item was independently confirmed: the LV reference state is exactly the equilibrium (both derivatives zero, re-derived by hand and by execution), the pendulum reference genuinely had no recorded value, "grows roughly linearly" is falsified at the declared horizon, the invariant crosses zero inside the training box (min |V| ≈ 1.5e-6 over 100k samples), and ddof changes emitted bytes (differ at the 7th significant digit, not bit-identical). This is the executed-first discipline working as intended.
  • Two fixes are only half-done. A8 fixed persistence but not linear (the same file now runs two baselines under one ADR with two different ddof conventions). A7 replaced a divide-by-near-zero normaliser — correctly — but its shipped code pools the training and out-of-region starts into one span, contradicting the backlog's own stated rationale and the bound's stated purpose, and no one re-derived whether 1e-6 still means what it did.
  • Defect-class partitioning paid off. Contracts caught that A4's own correction text is incomplete. Requirements coverage caught two orphan fail-loud mechanisms with no phantom-gate case. Security reframed A9 from a layering nicety into a confidentiality-boundary gap the byte-identity backstop structurally cannot cover. None of these overlapped.

Critical Findings

C1 — A8 is only half-closed: the linear residual spread runs on ddof=0, unguarded and untested, while its own docstring claims parity with the persistence fix

Flagged by four panels (Quality Attributes rated it Critical; Contracts, Implementability, and the blind determinism panel rated it Important). src/wmj/models/baselines.py pins SPREAD_DDOF = 1 and applies it in the public, guarded fit_persistence_spread (which raises DegenerateSpreadError on a zero or non-finite fit). But _fit_linear_spread calls np.std(residual..., axis=0) with no ddof argument — NumPy's default ddof=0, the population estimator — and has no degeneracy guard and no test of its value. The module docstring states linear "uses the same Bessel correction," a parity the code does not keep. Under NF-1 this changes the emitted bytes of every downstream CRPS, skill score, and Verdict, exactly as A8 argues for persistence. The docstring discloses this as deferred to P3-C02, so it is tracked, not hidden, and nothing ships broken today — but A8 cannot be marked resolved while it is open, and no test would catch a P3-C02 implementation that "refines" linear without matching ddof=1. Fix: pin ddof=1 in _fit_linear_spread, route it through a guarded public fit_linear_spread mirroring persistence, add the value + degeneracy tests, and pin ddof=1 in ADR-M2 for both baselines with a cross-reference to ADR-M3's ensemble Bessel correction.

Important Findings

I1 — A7's shipped normaliser pools an out-of-distribution region into the denominator that is meant to protect the training-region climatology
The blind determinism panel executed the real pipeline at the production seed. build_divergence_artefact accumulates initial_values across every declared region (training and out-high-amplitude), so the emitted conserved_rel_drift_max = max drift / span-over-all-starts = 3.39e-8 — not the 6.7e-9 the backlog's own rationale states for the training region alone (a 5× discrepancy between stated rationale and shipped code). Pooling an out-of-distribution region inflates the denominator and deflates the reported drift for exactly the region the bound protects — the wrong direction for a safety gate — and entangles a would-be analytic quantity with n_starts and RNG sampling. LV's V is separably convex with its minimum at the equilibrium interior to the training box, so the per-region range is computable in closed form with no RNG. This is a shared function that runs unmodified for the pendulum. Fix: normalise by the conserved quantity's dynamic range computed per region, separately, by a deterministic method; assert TC-WD3-03 per region and report within_bound per region.
I2 — A7's normaliser swap changes what "within bound" means, and the 1e-6 constant was never re-derived under it
ADR-W1's 1e-6 bound was calibrated (implicitly) against a relative-to-initial normaliser and justified as "tight enough that the conditioned climatology cannot be corrupted by integrator error." Swapping the denominator to a span orders of magnitude larger means the same physical drift now clears the bound comfortably, with no re-derivation confirming the constant still delivers its stated protective purpose — a response-measure change riding inside a bug fix. Fix: a rough re-derivation (ADR-W1's own "preliminary hand calculation" style) of what integrator-error magnitude the new normalised 1e-6 actually catches, then re-pin or explicitly justify the loosening.
I3 — A9: reporting's stated layering has no mechanical gate, unlike the judge's and models'
Four panels. The judge and models packages each have an enforced import allowlist; reporting's identical ADR-003 layering claim ("matplotlib / numpy / stdlib / judge-types / own-package only") is enforced by nothing. Security's framing is the decisive one: reporting is the sole writer of the public out/ artefacts, so it is the last trust boundary before content becomes public (NF-4), and the byte-identity backstop cannot cover this failure mode — a deterministic leak (a home-directory path, hostname, or env var read via an accidentally-imported os/socket) is stable across all ten runs and so invisible to a gate that only flags variation. Reporting is also, by review-round count, the most drift-prone spec in the project. Fix: add a REPORTING_ALLOWLIST and a test mirroring the models gate (framed honestly as lint, not proof), or record a reasoned ADR distinction for why reporting is treated differently. Recommendation from three of four panels: add the gate.
I4 — A1/A2/A6: the spec documents still carry the traps the build already fixed in code
specs/worlds.md §8 still pins the LV reference at the degenerate equilibrium (4.0,2.5) and still says the pendulum value "must be recomputed" while recording none; ADR-W3 and TC-WD4-01 still say the LV divergence curve "grows roughly linearly." A reviewer reading the spec as the standard would flag the correct test code as non-conforming. Fix this round: update §8 to (4.5,2.0) with the degeneracy reasoning, pin the recomputed pendulum constant with its two-method concordance, and reword the divergence claims to "bounded / sub-exponential over the declared horizon." Blind panel condition: give A1's (4.5,2.0) a second independent verification before pinning, matching A2.
I5 — A4's own correction text is incomplete: it omits __future__
A4 proposes adding wmj.errors and hashlib to the models allowlist, but the built gate allows MODELS_ALLOWLIST | ALWAYS_ALLOWED where ALWAYS_ALLOWED = {"__future__"}, and every models file uses from __future__ import annotations. A5 names __future__ for the judge; A4 must name it for models too, or applying A4 verbatim leaves the corrected sentence still false — the exact drift this round exists to close.
I6 — Two new fail-loud mechanisms are orphans with no phantom-gate case
The structural metaclass= check (A3) and DegenerateSpreadError (A8) are code mechanisms with no tracing test case, and — against the project's own convention that every fail-loud gate needs a negative case proving it can fire — no phantom-gate case. TC-NF6-02's disclaimer absorbs the ten new identifier names, but the metaclass check is a structurally different AST shape it does not reach. Fix via /gvm-test-cases: add a class X(metaclass=Y) case tracing to NF-6 and a zero/non-finite-spread → DegenerateSpreadError case tracing to MU-2.
B1 — accept the coverage gap, decline the same-round build
Two panels agree the action-blind model check is a genuine gap (grep-confirmed: nothing checks a model's prediction changes when only the action changes; TC-WD2-01 checks the world's lever) and is INVEST-compliant. It is not goalpost-moving: it is an externally-sourced fixture (a fourth engineered failure mode under MU-3's explicit "at minimum" list, pre-registration-exempt), and declining to quietly patch it in is the correct behaviour. Route it through requirements → test-cases → design-review → build: add an explicit fourth MU-3 bullet + TC-MU3-04, with its pass/fail condition fixed at requirements time. The user makes the final ACCEPT/DECLINE call.
